## Q1. FreeLang이라는 언어는 처음 들어봐요. 왜 새 언어를 만드나요?

**A.**

"또 새 언어냐"는 반응, 충분히 이해합니다. 우리도 처음엔 기존 언어로 해결하려 했어요.

FreeLang은 범용 언어가 목표가 아닙니다. **UI 컴포넌트를 선언적으로 정의하는 경량 DSL**입니다. 기존 언어(React JSX, Vue SFC, Svelte)를 쓸 수도 있지만, 각각 런타임 번들, 빌드 체인, 특정 프레임워크와의 결합이 따라옵니다.

FreeLang은 그 반대를 선택했습니다. 컴파일러가 HTML/CSS/JS를 직접 생성하고, 런타임 의존성이 없습니다. FreeWire는 그 FreeLang을 시각 편집기로 만드는 도구입니다.

"작은 범위의 문제를 단순하게 푼다"는 것이 핵심입니다.

## Q2. 비슷한 도구들(Node-RED, Blueprints, Scratch)이 이미 있는데 차별점이 뭔가요?

**A.**

좋은 기준점을 짚어주셨어요. 아래처럼 정리할 수 있습니다.

| 도구 | 강점 | FreeWire와 다른 점 |
|------|------|--------------------|
| Node-RED | IoT/서버 플로우 | FreeWire는 UI 컴포넌트 타겟 |
| Blueprints | 게임 로직 | FreeWire는 웹 컴포넌트, 브라우저 단독 실행 |
| Scratch | 교육용 | FreeWire는 실제 배포 가능한 코드 생성 |

결정적 차이는 **Intent 엔진**입니다. 기존 시각 도구들은 "연결이 맞는가(구조적 정확성)"만 검사합니다. FreeWire는 "이 노드가 목적에 맞게 연결됐는가(의미적 정확성)"도 0-100점으로 평가합니다. 실수를 단순히 허용하는 것이 아니라 사전 경고 + 자동 수정 제안까지 제공합니다.

## Q3. "162개 테스트 통과"라고 하는데, 어떤 내용을 테스트했나요?

**A.**

실제 수치이고, 각 Phase에서 단위 테스트를 누적했습니다.

- Phase 1 (32): 노드 JSON 스펙 — 노드 생성, 연결, 직렬화/역직렬화
- Phase 2 (16): Graph→FreeLang 컴파일러 — 노드 → `.free` 코드 변환 정확도
- Phase 3 (24): API 서버 + FreeExecutor — `.free` → HTML/CSS/JS 변환 파이프라인
- Phase 4 (30): 노드 에디터 UI — 드래그, 연결, 줌, Undo/Redo 로직
- Phase 5 (35): AI 자동 생성기 — 자연어 → 노드 15개 타입 생성 정확도
- Phase 6 (25): 브라우저 Live Preview — iframe 렌더링, 브라우저 단독 실행 검증

테스트 코드는 GOGS 저장소 `src/test/` 에서 확인할 수 있습니다.

## Q4. 실제로 사용할 수 있는 수준인가요? 프로덕션에서 쓸 수 있나요?

**A.**

솔직하게 말씀드리겠습니다. **현재는 초기 단계**입니다.

가능한 것:
- 간단한 UI 컴포넌트 시각 편집 + 코드 생성
- 브라우저에서 서버 없이 Live Preview 확인
- AI로 자연어 입력 → 노드 그래프 자동 생성

아직 미완성인 것:
- FreeLang 컴파일러의 WASM 포팅 (개발 예정)
- 복잡한 상태 관리 컴포넌트 (현재 단순 state만)
- 협업 편집 기능 없음
- 패키지 생태계 없음

"프로토타이핑, 학습, 아이디어 검증"에는 지금도 쓸 수 있습니다. 실제 서비스 배포는 아직 이릅니다.

## Q5. 성능은 어떤가요? 다른 프레임워크보다 빠른가요?

**A.**

현시점에서 "더 빠르다"고 주장하지 않겠습니다. 근거 있는 것만 말씀드릴게요.

**확인된 것**: FreeExecutor가 생성하는 코드는 런타임 의존성이 없습니다. React/Vue/Svelte처럼 가상 DOM이나 반응성 런타임 번들이 없기 때문에 **초기 로드 크기**는 유리합니다.

**확인 안 된 것**: 복잡한 UI 업데이트 성능, 대규모 컴포넌트 트리에서의 재렌더링 속도.

공정한 벤치마크를 아직 진행하지 않았습니다. 진행 후 결과를 투명하게 공개하겠습니다. 지금 당장은 "런타임 번들 없음"이라는 구조적 특성만 말씀드릴 수 있습니다.

## Q6. AI 노드 자동 생성은 어떻게 동작하나요? 정확도는?

**A.**

자연어 입력 → Claude API → 노드 그래프 JSON 생성 파이프라인입니다.

예: `"로그인 폼을 만들어줘"` → 입력 노드(이메일, 비밀번호) + 버튼 노드 + 유효성 검사 노드 + 출력 노드가 자동으로 연결됩니다.

현재 지원하는 15개 노드 타입:
- 기본 UI: Button, Input, Card, Container, Text
- 상호작용: State, Event, Condition
- 레이아웃: Row, Column, Grid
- 데이터: Output, Computed, Transform, API

**정확도**: Phase 5 테스트 35개 기준으로 예상 노드 타입과 연결 관계를 검증했습니다. 단순한 컴포넌트 설명은 잘 생성되고, 복잡한 논리 흐름은 수동 조정이 필요한 경우가 있습니다.

API 키(Claude API)는 직접 발급하셔야 하며, 서버(`src/api/server.js`) 환경 변수로 설정합니다.

## Q7. Intent 엔진이 "계약 위반"을 잡는다고 했는데, 어떤 경우에 작동하나요?

**A.**

구체적인 예로 설명드릴게요.

**Button 노드**에는 `contract`가 있습니다: "반드시 `onClick` 이벤트 노드와 연결되어야 한다." 이 Button을 State 노드에만 연결하고 onClick 연결을 빠뜨리면, Intent 엔진이 이를 감지하고 점수를 낮추며 "onClick 연결 필요" 패치를 제안합니다.

**Goal** 측면에서는: Container 노드의 goal이 "자식 노드를 1개 이상 포함해야 한다"인데 빈 Container가 있으면 경고합니다.

실제로 유용한 케이스는 **학습 기억** 기능입니다. "Input 노드를 State에 연결하지 않고 Output에 바로 연결하는 실수"가 저장소에 3번 이상 기록되면, 다음에 같은 패턴을 시도할 때 미리 경고가 뜹니다. localStorage에 저장되므로 브라우저를 닫아도 유지됩니다.

## Q8. 외부 의존성이 없다고 했는데, 정말로 서버 없이 실행되나요?

**A.**

네, 기본 에디터는 서버 없이 실행됩니다.

```bash
python3 -m http.server 5500 --directory www
```

위 명령어는 정적 파일 서빙만 합니다. 실제 노드 편집, Graph 컴파일, Live Preview 모두 브라우저 내에서 동작합니다. Node.js 설치도 필요 없습니다.

단, AI 자동 생성 기능과 서버 측 FreeLang 실행은 `node src/api/server.js`가 필요합니다. 이건 선택적 기능입니다.

"서버 없이 실행"은 **브라우저 에디터의 핵심 기능에 대해서만** 성립합니다. 오해가 없도록 말씀드렸습니다.

## Q9. FreeLang과 FreeWire의 관계는 정확히 뭔가요? 따로 쓸 수 있나요?

**A.**

둘은 별도의 프로젝트입니다.

- **FreeLang**: UI 컴포넌트를 선언적으로 작성하는 DSL. `.free` 파일로 직접 코드를 작성할 수 있습니다.
- **FreeWire**: FreeLang 코드를 시각 편집기로 생성하는 도구. 코드 없이 노드 연결로 `.free` 파일을 만들어줍니다.

FreeWire 없이도 FreeLang을 쓸 수 있습니다. 반대로 FreeWire 없이는 의미가 없죠 — FreeWire의 최종 출력물이 FreeLang 코드이니까요.

"코드를 쓰기 싫다" → FreeWire 에디터 사용
"코드로 직접 제어하고 싶다" → FreeLang 직접 작성
두 경로를 모두 지원합니다.
