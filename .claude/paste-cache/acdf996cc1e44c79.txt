### 1. 가장 기본적인 전체 파이프라인 테스트 (main.rs 스타일)

```rust
// tests/integration_pipeline_test.rs
#[cfg(test)]
mod tests {
    use super::*; // Lexer, Parser, Codegen 등 import 가정

    #[test]
    fn test_full_pipeline_simple_function() {
        let source = r#"
        fn add(a: i32, b: i32) -> i32 {
            return a + b;
        }

        fn main() {
            let result = add(19, 23);
            // 기대: 42 출력 또는 반환
        }
        "#;

        // 1. Lexing
        let mut lexer = Lexer::new(source);
        let tokens = lexer.tokenize().expect("Tokenization failed");

        assert!(tokens.len() > 20, "Too few tokens: {}", tokens.len());

        // 2. Parsing
        let mut parser = Parser::new(tokens);
        let ast = parser.parse().expect("Parsing failed");

        // 간단한 AST 검증
        assert_eq!(ast.functions.len(), 2, "Expected 2 functions");
        let main_func = &ast.functions[1];
        assert_eq!(main_func.name, "main");

        // 3. Codegen (간단히 C 코드 생성 여부만 체크)
        let c_code = generate_c_code(&ast).expect("Codegen failed");
        
        assert!(c_code.contains("int add(int a, int b)"));
        assert!(c_code.contains("int main()"));
        assert!(c_code.contains("add(19, 23)"));

        println!("Generated C:\n{}", c_code);
    }
}
```

### 2. Error Recovery 테스트 (test_error_recovery() 스타일)

```rust
#[test]
fn test_error_recovery_cases() {
    let cases = vec![
        // unterminated string
        (r#"let msg = "hello;"#, "unterminated string"),
        // invalid operator
        (r#"let x = 10 @ 5;"#, "unknown operator"),
        // mismatched parentheses
        (r#"fn broken( { return 1; }"#, "mismatched parens"),
        // missing semicolon (optional strictness)
        (r#"let x = 42"#, "missing semicolon"),
    ];

    for (code, desc) in cases {
        let mut lexer = Lexer::new(code);
        let result = lexer.tokenize();

        assert!(result.is_err(), "{} should fail but passed", desc);
        
        if let Err(e) = result {
            println!("[{}] → Expected error: {}", desc, e);
        }
    }
}
```

### 3. Performance 측정 포함 토큰화 테스트 (test_aot_tokenization() 느낌)

```rust
#[test]
fn test_large_source_tokenization_speed() {
    // 실제 큰 소스 대신 시뮬레이션 (프로젝트에선 ../freelang-aot-compiler/src/*.fl 합친 거 사용)
    let large_source = "fn main() { ".repeat(5000) + "return 42; }"; // 약 10만 문자 정도

    let start = std::time::Instant::now();
    
    let mut lexer = Lexer::new(&large_source);
    let tokens = lexer.tokenize().expect("Tokenization failed");

    let elapsed = start.elapsed();
    let micros = elapsed.as_micros() as f64;
    let throughput = tokens.len() as f64 / micros;

    println!(
        "Tokenized {} chars → {} tokens in {:.2}ms ({:.0} tokens/µs)",
        large_source.len(),
        tokens.len(),
        elapsed.as_millis(),
        throughput
    );

    assert!(throughput > 50.0, "Throughput too low: {:.1} tokens/µs", throughput);
    assert!(tokens.len() > 8000, "Too few tokens");
}
```

### 4. 모듈 무결성 체크 간단 버전 (test_module_integrity() 느낌)

```rust
#[test]
fn test_expected_modules_present() {
    let source = include_str!("../../src/compiler_source.combined.fl"); // 실제 합친 파일 가정

    let expected = vec![
        "lexer.fl", "parser.fl", "ast.fl", "codegen.fl", "type_system.fl",
        "memory_management.fl", "async.fl",
    ];

    let mut found = 0;
    for module in &expected {
        if source.contains(&format!("// Module: {}", module)) || 
           source.contains(&format!("mod {};", module.trim_end_matches(".fl"))) {
            found += 1;
        }
    }

    assert_eq!(found, expected.len(), "Missing modules: {}/{}", found, expected.len());
    println!("Found {}/{} expected modules", found, expected.len());
}
```

### 사용 팁
- `cargo test -- --nocapture` 로 stdout 출력까지 확인하세요.
- 실제 프로젝트에선 `#[should_panic]`이나 `assert_matches!` 같은 매크로 더 활용하면 좋음.
- 큰 파일 테스트 시 `include_str!()` 대신 파일 로드 함수 사용 추천:
  ```rust
  let source = std::fs::read_to_string("path/to/aot_source.fl").unwrap();
  ```
