FVX의 핵심 엔진이 완성되었으니, 이제 이 엔진이 얼마나 강력한지 증명할 **'수학적 정밀도'**를 테스트할 예제들이 필요합니다. 단순한 로직 확인을 넘어, Solver가 공리(Axiom)를 바탕으로 모순을 찾아내거나 불변성(Invariant)을 증명하는 시나리오를 구성하는 것이 핵심입니다.
다음은 **Phase I (예제 확장)**를 위해 권장하는 3가지 카테고리의 수학적 증명 예제 설계안입니다.
1. 산술 불변성 및 경계 검사 (Arithmetic Invariants)
가장 기초적이면서도 Solver의 전파(Propagation) 능력을 테스트하기 좋습니다.
 * 예제명: range_check.fvx
 * 증명 목표: 루프 내에서 변수 x가 특정 범위 $[0, 100]$을 절대 벗어나지 않음을 증명.
 * 체크 포인트: * 공리 정의: x_{next} = (x + 1) \pmod{101}
   * Solver가 FixedPoint에 도달했을 때 x \leq 100이 유지되는지 확인.
2. 정렬 알고리즘의 단조 증가성 (Monotonicity)
이미 253 서버에서 검증한 '정렬' 로직을 더 엄밀하게 수식화합니다.
 * 예제명: sort_verify.fvx
 * 증명 목표: 임의의 인덱스 i, j에 대해 $i < j \implies array[i] \leq array[j]$임을 증명.
 * 체크 포인트: * FreeJulia IR에서 넘어온 배열 제어 흐름이 FVX IR의 인덱스 공리와 충돌하지 않는지 분석.
   * Swap 연산 전후의 인접 요소 대소 관계 변화 추적.
3. 재귀 함수의 정지 문제 및 자원 할당 (Termination & Resource)
피보나치 예제를 확장하여 시스템의 안전성을 검증합니다.
 * 예제명: fib_safety.fvx
 * 증명 목표: 입력값 n에 대해 재귀 깊이가 k를 초과하지 않으며, 스택 오버플로가 발생하지 않음을 증명.
 * 체크 포인트:
   * 공리: Fib(n) = Fib(n-1) + Fib(n-2) (단, n > 1)
   * Solver 스케줄러가 재귀 호출의 의존성 그래프를 순환 없이(DAG) 풀어내는지 확인.
📝 예제 파일(.fvx) 작성을 위한 가이드라인
.fvx 파일은 엔진이 읽기 가장 좋은 형태로 작성되어야 합니다. 다음과 같은 구조를 제안합니다.
// fvx 예제 규격 제안
AXIOM {
    ASSERT x >= 0;
    DEFINE STEP(x) -> (x + 1);
}

MATCH IR {
    BRIDGE "FreeJulia::Loop_Start";
    INVARIANT x < LIMIT;
}

SOLVE {
    STRATEGY FixedPoint;
    SCHEDULE PriorityQueue;
}
