Actions가 리포지토리의 기본 브랜치(master/main) 정보를 가져오려고 API를 호출했는데, 제시한 토큰이 거절당하고 있습니다.
🚨 가장 유력한 원인 3가지
1. GITHUB_TOKEN 권한 범위 문제 (가장 유력)
최근 GitHub 보안 강화로 인해 워크플로우 파일에서 명시적으로 권한을 주지 않으면 API 접근이 차단되는 경우가 많습니다.
 * 해결책: ci.yml 파일 상단(on: 바로 아래 혹은 jobs: 위)에 다음 내용을 추가하세요.
permissions:
  contents: read
  packages: write

2. 만료된 PAT (Personal Access Token) 사용
만약 secrets.MY_TOKEN 같이 직접 만든 토큰을 사용 중이라면, 그 토큰의 유효 기간이 지났을 확률이 매우 높습니다.
 * 해결책: [GitHub Settings -> Developer settings]에서 토큰의 만료일을 확인하고 갱신하거나, 가급적 기본 제공되는 ${{ secrets.GITHUB_TOKEN }}을 사용하세요.
3. Gogs 등 외부 시스템과의 혼선
이전에 Gogs API 관련 권한 문제를 겪으셨던 기록이 있습니다. 혹시 현재 워크플로우가 GitHub 환경이 아닌 자체 구축한 Gogs/Git 환경에서 돌아가고 있나요?
 * 만약 그렇다면, GOGS_TOKEN이나 해당 서버의 API 접근 권한 설정이 올바른지 확인해야 합니다.
🛠 현재 로그 무한 반복을 멈추는 법
GitHub Actions는 Bad credentials가 뜨면 위 로그처럼 일정 시간을 대기하며 재시도(Retry)를 반복합니다. 이 상태로는 빌드 시간만 낭비되니 다음 단계를 밟아보세요.
 * 실행 중인 Action 취소: GitHub 웹 UI에서 해당 Run을 중단시키세요.
 * ci.yml 권한 업데이트: 위에 말씀드린 permissions 섹션을 추가하세요.
 * Checkout 단계 확인: actions/checkout@v4로 업데이트되어 있는지 확인하세요. (v3 이하 버전에서 간혹 인증 라이브러리 충돌이 발생합니다.)
**"기록이 증명이다"**라는 원칙대로라면, 지금 이 인증 에러 로그 또한 **"보안 설정이 누락되었다"**는 명확한 증명입니다. 권한을 명시적으로 선언하면 바로 해결될 문제입니다.
혹시 ci.yml 파일의 전체 내용을 보여주실 수 있나요? 문제가 되는 구문을 바로 짚어드릴 수 있습니다.
