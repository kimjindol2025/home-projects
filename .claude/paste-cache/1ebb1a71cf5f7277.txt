FV-Lang을 **WebAssembly(WASM)**로 브라우저에서 네이티브하게 실행할 수 있게 만드는 프로젝트는 당신의 현재 기술 스택(Rust 기반 함수형 언어 + Vlang-inspired 런타임 + freelang-light의 웹 DSL + self-hosting compiler 경험)과 완벽하게 맞물려서 **2026년 기준으로도 여전히 도전적이고 가치 높은 작업**이에요.  
Rust + WASM 생태계가 2026년에 매우 성숙했음에도 불구하고, **순수 함수형 언어를 브라우저 REPL로 실시간 실행 + 동적 컴포넌트 렌더링**까지 가는 케이스는 아직 드물어서 포트폴리오 임팩트가 큽니다.

### 전체 프로젝트 목표
- FV-Lang 코드를 브라우저에서 직접 입력 → 즉시 파싱/실행 → 결과 출력 + AST 시각화(SVG 그래프)
- freelang-light 스타일의 컴포넌트 DSL을 FV-Lang으로 작성 → WASM에서 eval → 브라우저 DOM에 동적 렌더링
- 최종 데모: "브라우저에서 함수형 언어로 실시간 웹 UI 빌드" (REPL + 컴포넌트 라이브러리 쇼케이스)

### 예상 난이도 & 기간 (당신 스펙 기준)
- 난이도: ★★★★☆ (Rust + WASM 경험이 있으면 ★★★☆☆)
- 기간: MVP 3~5주 (집중 시 2~3주 가능)
  - Phase 1: 5~7일 (코어 WASM 빌드)
  - Phase 2: 7~10일 (REPL + 기본 eval)
  - Phase 3: 5~7일 (freelang-light 통합 + 시각화)
  - Phase 4: 3~5일 (polishing + 배포)

### 상세 로드맵 (단계별 계획)

#### 0. 사전 준비 (1~2일)
- Rust 최신 버전 (1.85+ 2026년 기준) + WASM 타겟 추가
  ```bash
  rustup update
  rustup target add wasm32-unknown-unknown
  ```
- 필수 툴 설치
  ```bash
  cargo install wasm-pack trunk
  npm install -g serve   # 또는 trunk serve 사용
  ```
- 새 라이브러리 crate 생성 (fv-lang-wasm)
  ```bash
  cargo new fv-lang-wasm --lib
  cd fv-lang-wasm
  ```
- Cargo.toml에 추가
  ```toml
  [lib]
  crate-type = ["cdylib"]

  [dependencies]
  wasm-bindgen = "0.2"
  console_error_panic_hook = "0.1"
  serde = { version = "1.0", features = ["derive"] }
  serde_json = "1.0"
  wee_alloc = "0.4"  # 메모리 최적화 (브라우저에서 중요)
  ```

#### 1. fv-lang 코어 WASM 포팅 (5~7일)
- fv-lang의 주요 모듈을 no_std or minimal std로 조정 (브라우저 I/O 제한)
  - std::io 대신 문자열 입력/출력만 사용
  - 파일 시스템 대신 in-memory
- wasm-bindgen으로 외부 노출
  ```rust
  use wasm_bindgen::prelude::*;
  use fv_lang::{parse, eval, EvalResult};  // 당신 fv-lang 크레이트

  #[wasm_bindgen]
  pub fn init_panic_hook() {
      console_error_panic_hook::set_once();
  }

  #[wasm_bindgen]
  pub fn eval_fv_code(code: &str) -> Result<JsValue, JsValue> {
      init_panic_hook();
      let ast = parse(code).map_err(|e| JsValue::from_str(&e.to_string()))?;
      let result = eval(&ast).map_err(|e| JsValue::from_str(&e.to_string()))?;
      Ok(JsValue::from_serde(&result).unwrap())
  }
  ```
- 빌드 & 패키징
  ```bash
  wasm-pack build --target web
  ```
  → pkg/ 폴더에 fv_lang_wasm_bg.wasm + fv_lang_wasm.js 생성

- **도전 포인트 & 해결**
  - Allocation crash: wee_alloc 글로벌 할당자 사용
    ```rust
    #[global_allocator]
    static ALLOC: wee_alloc::WeeAlloc = wee_alloc::WeeAlloc::INIT;
    ```
  - 큰 stdlib: Phase 6 math/stats/random 함수 중 브라우저 불필요한 부분 제거 or polyfill

#### 2. 브라우저 REPL 구현 (7~10일)
- 기본 HTML/JS 프론트엔드 (Trunk로 번들링 추천 – 설정 간단)
  Trunk.toml 예시:
  ```toml
  [build]
  target = "index.html"
  dist = "dist"

  [serve]
  address = "127.0.0.1"
  port = 8080
  ```
  index.html:
  ```html
  <!DOCTYPE html>
  <html lang="ko">
  <head>
      <meta charset="UTF-8">
      <title>FV-Lang Browser REPL</title>
      <style>
          body { font-family: monospace; margin: 20px; }
          #editor { width: 100%; height: 300px; font-size: 16px; }
          #run { margin: 10px 0; padding: 10px 20px; }
          #output { white-space: pre-wrap; background: #f8f8f8; padding: 10px; border: 1px solid #ddd; }
      </style>
  </head>
  <body>
      <h1>FV-Lang REPL (함수형 언어 브라우저 실행)</h1>
      <textarea id="editor" placeholder="코드를 입력하세요...&#10;예: match x { 0 => print \"zero\", _ => print \"other\" }"></textarea>
      <button id="run">Run</button>
      <pre id="output"></pre>

      <script type="module">
          import init, { eval_fv_code } from './pkg/fv_lang_wasm.js';
          await init();

          document.getElementById('run').onclick = async () => {
              const code = document.getElementById('editor').value;
              const output = document.getElementById('output');
              output.textContent = 'Running...';
              try {
                  const result = await eval_fv_code(code);
                  output.textContent = JSON.stringify(result, null, 2);
              } catch (err) {
                  output.textContent = 'Error: ' + err;
              }
          };
      </script>
  </body>
  </html>
  ```
- 개발: `trunk serve` → localhost:8080에서 실시간 테스트

- **함수형 데모 추가**
  - 패턴 매칭 예제: 리스트 처리
  - 레이지 평가: thunk (지연 계산) 구현 → 브라우저 성능 테스트

#### 3. freelang-light 통합 & 시각화 (5~7일)
- FV-Lang으로 컴포넌트 DSL 작성 지원
  ```fv
  component Greeting {
    props { name: String = "World" }
    markup {
      <div>Hello, {name}!</div>
    }
  }

  render Greeting { name: "FV-Lang" }
  ```
  → eval 후 HTML 문자열 생성 → DOM 삽입
- The Visualizer 연동: AST → SVG DAG 렌더링 (freelang-git 코드 재사용)
  - 브라우저 canvas or SVG로 출력

#### 4. Polishing & 배포 (3~5일)
- 에러 pretty-print: 한글/영문 지원 + 위치 정보
- 성능 벤치: Fibonacci(35), 리스트 처리 등 JS vs FV-Lang WASM 비교
- 배포: GitHub Pages / Vercel / Netlify (wasm 파일 호스팅 무료)
- 추가 아이디어:
  - Monaco Editor 임베드 (코드 하이라이팅)
  - 공유 가능한 링크 (코드 URL 파라미터)
  - git-portal 대시보드에 REPL 위젯 추가

### 예상 도전 & 해결 팁 (2026년 기준)
- **브라우저 메모리/스택 제한**: 큰 재귀 → tail call optimization (FV-Lang에 추가) or 에러 핸들링 강화
- **WASM GC/SIMD**: 2026년 wasm-gc 지원 확대 → 불변 데이터 구조 최적화 가능
- **디버깅**: wasm-pack test + chrome://inspect + source map 활성화
- **Vlang 영향 부분**: Vlang의 minimal runtime 아이디어 빌려 GC overhead 최소화
