The World Engine은 단순한 개발 도구가 아니라, 코드가 '고정된 실체'에서 '필요에 따라 생성되고 소멸하는 생체 에너지'로 전환되는 지점입니다.
김진돌 님이 구축해오신 FreeLang 에코시스템이 드디어 하나의 생명체로 조립되는 과정이죠. "평범한 코딩"이 지루했던 이유는 결과물이 정적이었기 때문인데, 이 시스템은 **의도(Intent)**라는 입력에 따라 아키텍처를 '배설'하고 스스로 형태를 결정합니다.
가장 임팩트가 클 Phase 0: Intent Parser를 FreeLang 기반으로 설계해 보겠습니다.
Phase 0: Intent Parser (The Seed of World)
단순히 자연어를 코드로 바꾸는 것이 아니라, **의도를 정형화된 논리 구조(Intent Graph)**로 추출하는 것이 핵심입니다.
1. Intent DSL 정의 (FreeLang 기반)
FreeLang 내부에 의도를 정의하는 전용 구문을 설계합니다. 이 구문은 KimDB, PolyglotAPI, FreeWire를 관통하는 메타 데이터가 됩니다.
// FreeLang Intent Specification (draft)
intent InventoryWorld {
    context {
        lifecycle: ephemeral(2h),
        storage: KimDB.memory_buffer, // 고성능 메모리 우선
    }

    schema Product {
        id: uuid @primary,
        name: string @required,
        qty: int @default(0) @check(qty >= 0),
    }

    action stock_in(product_id, amount) {
        update Product set qty = qty + amount where id = product_id;
    }

    view Dashboard {
        type: Grid,
        source: Product,
        interact: [stock_in],
    }
}

2. LLM to FL-Intent Mapper
사용자의 모호한 한마디를 위와 같은 FL-Intent 구조로 변환하는 레이어입니다.
 * Input: "재고가 0 미만이 되지 않는 간단한 창고 관리 앱 만들어줘."
 * Reasoning: 1.  Entity 추출 → Product
   2.  Constraint 파악 → qty >= 0
   3.  UI 유추 → 입/출고 기능이 포함된 대시보드.
 * Output: 유효성 검사가 완료된 InventoryWorld.fl 생성.
아키텍처의 핵심: "의도의 전이"
World Engine의 진정한 강력함은 **의도가 각 컴포넌트로 전이(Propagation)**되는 방식에 있습니다.
| 단계 | 전이 로직 (The Flow of Intent) |
|---|---|
| Data Layer | schema 정보를 읽어 KimDB 테이블을 즉시 프로비저닝. |
| API Layer | action을 분석해 PolyglotAPI에 REST 엔드포인트 자동 바인딩. |
| UI Layer | view 정의에 따라 FreeWire 노드를 자동 배치하고 실시간 렌더링. |
| Cleanup | lifecycle 종료 시 모든 프로세스 킬 및 메모리 해제(Evaporation). |
특이점 포인트: "시스템의 결핍 감지"
여기서 한 발 더 나아가면, 사용자가 말하지 않은 **'필수 의도'**를 시스템이 제안하는 단계로 갈 수 있습니다.
 * 예: "재고 관리를 만든다면 유저 권한 설정(ACL)이 필요할 텐데, 추가할까요?"
 * 증명: 모든 생성 이력은 Gogs에 남으며, 시스템은 과거의 'World' 생성 패턴을 학습해 더 정교한 아키텍처를 배설합니다.

Phase 0의 핵심은 **"자연어를 FL-Intent DSL로 얼마나 정확하게 정제하느냐"**입니다.
 * Intent DSL 명세 확립: FreeLang으로 intent, schema, action 등의 키워드를 처리하는 파서를 먼저 짤까요?
 * Schema Synthesizer (Phase 1): DSL 한 줄로 KimDB가 즉시 물리적 테이블을 생성하는 '즉각적 실체화'부터 구현해 볼까요?
