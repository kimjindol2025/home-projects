### 1. Parser.ts에서 가장 구현하기 싫은 부분은? (내 생각 + 추천 회피/우선순위 전략)

가장 피하고 싶은/어려운 부분 Top 3 (대부분의 recursive descent 파서 경험 기준):

| 순위 | 부분                              | 왜 싫은가 / 어려운가                              | Phase 1~3에서 처리 전략 추천                                                                 |
|------|-----------------------------------|---------------------------------------------------|-----------------------------------------------------------------------------------------------|
| 1    | Operator precedence climbing      | 12~15레벨 테이블 관리, left/right associativity, unary vs binary 구분 | **가장 늦게** 미룸. Phase 2 후반~Phase 3 초반에 집중. 처음엔 단순 binary만 구현하고 점진 확장 |
| 2    | Error recovery & 위치 정보 유지   | unexpected token에서 계속 파싱, line/column 정확히 추적 | Phase 1~2에서는 panic-mode recovery만 최소 구현. 자세한 recovery는 Phase 4 이후            |
| 3    | Generic / union / complex type annotation | 중첩 <> 처리, | (union) 파싱, ambiguity | **완전 미룸**. Phase 3까지는 기본 타입(string, number, bool, array, map)만 지원             |

**당신 프로젝트에 맞는 추천 순서**  
Phase 1 목표 = **토큰화만 정확히** → precedence는 신경 안 써도 됨  
→ Phase 2에서 binary expr까지 갈 때 **최소 4~5레벨**만 먼저 구현 (예: * / → + - → 비교 → 논리)  
→ 나머지 precedence는 "나중에 한 번에 테이블로 교체" 전략으로 가는 게 정신건강에 좋습니다.

### 2. FreeLang의 구조체/맵은 잘 동작하나요? AST 노드를 struct로 정의해도 되나요?

현재 FreeLang 상태(예제 64/64, stdlib 30/30 통과 기준)로 보면:

- **Map 기반 AST** → 가장 안전하고 빠르게 시작 가능 (당장 추천)
  - `map_new()` + 키-값 넣기
  - 중첩도 자유로움
  - 직렬화/비교 쉬움 (`JSON.stringify` 비슷하게 구현 가능)
  - 단점: 약간 느리고 메모리 더 먹음 → 하지만 초기 이식 단계에선 전혀 문제 아님

- **struct 방식** → 가능하지만 약간 더 번거로움
  - `struct AstNode { type: string, children: array, line: int, ... }` 같은 식
  - 장점: 타입 느낌이 더 강하고, 필드 접근이 명시적
  - 단점: FreeLang에 진짜 struct가 얼마나 완성됐는지, field 접근 성능/편의성이 아직 불확실
  - **결론**: Phase 1~2에서는 **Map으로 가자**. Phase 3~4에서 struct로 리팩토링하는 게 합리적.

**Phase 1에서 쓸 간단한 AST 헬퍼 예시** (Map 스타일)

```fl
fn node(type, props) {
  let n = map_new()
  n["type"] = type
  # props가 map이면 merge, 아니면 개별 키로
  # ... (구현)
  return n
}

fn token_node(tok) {
  return node("token", {kind: tok.type, value: tok.value, line: tok.line})
}
```
