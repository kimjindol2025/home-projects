 계획 세우고, "이 작업 어떻게 할까?" 판단 → 도구(tools/skills)를 선택 → 실행 명령 내림.
- **스크립트 부분** (실행 엔진): Node.js 기반으로 만들어진 **프레임워크 + 스크립트**예요. Gateway(항상 켜진 프로세스)가 메시지 받고, LLM 호출하고, LLM이 말한 대로 **스크립트/명령어/코드**를 실제로 돌려서 일을 함 (파일 열기, 브라우저 클릭, 쉘 명령, API 호출 등).

쉽게 비유하면:
- **스크립트만** → "이 명령어 쳐" 하면 그대로 실행하는 자동화 봇 (예: bash 스크립트나 AppleScript).
- **AI만** → ChatGPT처럼 말만 해주는 챗봇.
- **OpenClaw** → AI가 "이걸 어떻게 할지" 계획 세우고 → 그 계획대로 스크립트/도구를 자동으로 써서 **진짜 일**을 해냄. 그래서 "자율 에이전트(autonomous agent)"라고 불림.

### OpenClaw의 구조 (AI vs 스크립트 비율)
- **AI (주도권 70~80%)**: 
  - Reasoning Layer: LLM이 프롬프트 보고 "이 작업 분해 → 도구 선택 → 순서 결정".
  - Memory (SOUL.md, episodic/semantic/procedural 파일): AI가 장기 기억처럼 과거 대화·학습 유지.
  - Heartbeat: AI가 스스로 깨어나서 "오늘 할 일 체크"처럼 프로액티브하게 동작 (스크립트 cron + AI 판단 결합).

- **스크립트/코드 (실행 20~30%)**:
  - Gateway: Node.js로 항상 돌아가는 서버 (메시지 라우팅, 세션 관리).
  - Skills: TypeScript/Markdown으로 된 모듈 (예: github-skill.ts → octokit 써서 git push).
  - Execution Layer: LLM이 "이 코드 실행해" 하면 sandbox나 직접 쉘/브라우저에서 돌림 (Playwright, child_process 등).
  - 전체가 오픈소스라서 소스 코드 보면 대부분 **Node.js + LLM API 호출 + 파일 기반 상태 관리**임.

결과적으로:
- **AI가 없으면** → 그냥 스크립트 실행기 (무의미).
- **스크립트/프레임워크가 없으면** → LLM이 생각만 하고 아무것도 못 함.
- 그래서 **"AI가 스크립트를 동적으로 작성·실행하는 시스템"**이라고 보는 게 제일 정확해요.

kim님 프로젝트(freelang-nexus 등)랑 매치할 때도 이게 핵심:
- freelang-nexus의 dependency graph + 빌드 스크립트 → OpenClaw Skills로 만들어서 AI가 "fusion.free 빌드해줘" 하면 자동으로 계획 세우고 nexus run 실행.
- AI가 "이 Phase 어떻게 구현할까?" 판단 → 코드 제안 → git push까지.

**AI인가 스크립트인가?** → **AI가 뇌, 스크립트가 몸**인 하이브리드예요. 그래서 기존 자동화 스크립트보다 훨씬 똑똑하지만, 보안·비용·불안정성도 같이 따라옴.
