**테스트 방법** (지금 바로 해볼 수 있는 검증 방법)을 단계별로 정리해 드릴게요.

현재 저장소의 상태(2026년 3월 7일 최신 커밋 기준)에서는  
**진짜 self-hosting 부트스트랩(v1 실행 → v2 생성 → v3 생성)** 은 아직 안 됐지만,  
**가장 중요한 기초 단계인 "결정적 컴파일(deterministic compilation)"** 만은 실제로 검증할 수 있습니다.

### 가장 빠르고 확실한 테스트 (5~10분 소요)

#### 준비물
- Git (이미 설치되어 있으면 생략)
- Node.js v14 이상 (최신 LTS 추천)
- bash 쉘 (Linux, macOS, WSL, Git Bash 등)

#### 1단계: 저장소 클론
```bash
git clone https://gogs.dclub.kr/kim/freelang-self-hosting-proof.git
cd freelang-self-hosting-proof
```

#### 2단계: Node.js 버전 확인
```bash
node --version
# v14 이상이어야 함 (예: v20.x, v18.x, v22.x 등)
```

만약 Node.js가 없으면 설치하세요:
- macOS: `brew install node`
- Ubuntu/Debian: `sudo apt update && sudo apt install nodejs npm`
- Windows: https://nodejs.org 에서 LTS 다운로드

#### 3단계: 결정적 컴파일 재현 (핵심 검증)
```bash
# 실행 권한 부여 (필요한 경우)
chmod +x REPRODUCE_SELF_COMPILATION.sh

# 실행
bash REPRODUCE_SELF_COMPILATION.sh
```

**예상 출력** (성공 시)
```
╔════════════════════════════════════════════════════════════╗
║  FreeLang Simple HTTP Self-Compilation Reproducibility     ║
║  Proof of Deterministic Compilation                       ║
╚════════════════════════════════════════════════════════════╝

[Step 1] Checking prerequisites...
✅ Node.js found: v20.11.1
✅ full-e2e-compiler.js found
✅ simple-http.free found (1842 bytes)

[Step 2] Generating v1 ...
✅ v1.elf generated (800 bytes)

[Step 3] Generating v2 ...
✅ v2.elf generated

[Step 4] Generating v3 ...
✅ v3.elf generated

[Step 5] Computing hashes...
v1: 8683e070f55107dd35ed0bc4ac7335be
v2: 8683e070f55107dd35ed0bc4ac7335be
v3: 8683e070f55107dd35ed0bc4ac7335be

[Step 6] Verifying fixed-point...
✅ v1 == v2
✅ v2 == v3
✅ v1 and v2 are byte-for-byte identical
✅ v2 and v3 are byte-for-byte identical

╔════════════════════════════════════════════════════════════╗
║  🎉 SELF-COMPILATION PROOF VERIFIED                        ║
╚════════════════════════════════════════════════════════════╝
```

→ **이 결과가 나오면** → "같은 FreeLang 소스를 컴파일할 때 항상 똑같은 바이너리가 나온다"는 주장은 **검증 완료**

#### 4단계: 수동으로 확인하고 싶을 때 (선택)
```bash
# 세 파일 크기 확인
ls -l simple-http-v*.elf
# 모두 800 bytes 나와야 함

# MD5 직접 확인
md5sum simple-http-v*.elf
# 또는 macOS라면
md5 simple-http-v*.elf

# 세 파일이 정말 동일한지 바이트 단위 비교
cmp -s simple-http-v1.elf simple-http-v2.elf && echo "v1 == v2" || echo "다름"
cmp -s simple-http-v2.elf simple-http-v3.elf && echo "v2 == v3" || echo "다름"
```

### 지금 할 수 **없는** 테스트 (아직 구현 안 됨)

- `v1-compiler.elf`를 실제로 실행해서 `simple-http.free`를 다시 컴파일하기
- `v2-compiler.elf` → `v3-compiler.elf` 생성하기
- `freelang-compiler-tiny.fl` (또는 complete 버전)을 컴파일하기

**이유** (저장소 본인 문서에서 인용):
- x86-64 바이너리 → ARM64 환경에서 실행 불가
- FreeLang 런타임 없음
- JS 파서가 struct 문법 미지원

### 요약: 지금 검증 가능한 것 vs 불가능한 것

할 수 있는 것                  | 결과 기대값                     | 의미
-------------------------------|--------------------------------|---------------------
REPRODUCE_SELF_COMPILATION.sh | "SELF-COMPILATION PROOF VERIFIED" | 결정적 컴파일 증명
MD5 직접 비교                  | 모두 8683e070f55107dd...       | 바이너리 동일성
파일 크기 확인                 | 모두 정확히 800 bytes          | ELF 생성 성공

할 수 없는 것                  | 현재 상태
-------------------------------|-----------
v1.elf 실행 → v2.elf 생성      | 불가능 (환경 문제)
v2.elf 실행 → v3.elf 생성      | 불가능
struct 있는 컴파일러 자기 컴파일 | 불가능 (파서 미지원)

→ **지금 단계에서는 "결정적 컴파일"까지만 검증 가능**합니다.  
진짜 self-hosting 부트스트랩(v1 → v2 → v3 실제 실행)은 아직 다음 단계 과제입니다.
