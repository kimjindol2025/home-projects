🛠️ 1.5단계: 인프라 기초 공사 (실제 동작용)
tree.fl이 제대로 돌아가려면 simpleHash와 writeFile 같은 기초 함수들이 연결되어야 합니다.
crypto.fl (최소 구현)
완벽한 SHA1 대신, 프리랭 환경에서 즉시 테스트 가능한 간단한 해시 함수를 배치합니다.
# crypto.fl
fn simpleHash(data: string): string {
    # 아주 간단한 해시 로직 (테스트용)
    # 실제 구현 시에는 SHA-1 알고리즘으로 교체 예정
    let h = 0
    for i in 0..len(data) {
        h = (h * 31 + charCodeAt(data, i)) % 1000000000
    }
    return toString(h) # 실제로는 40자 16진수 문자열이 되어야 함
}

storage.fl (최소 구현)
파일을 쓰고 읽는 실제 I/O를 담당합니다.
# storage.fl
fn writeFile(path: string, content: string): bool {
    # 실제 시스템 콜 호출 (FreeLang 내장 함수 가정)
    return __native_write_file(path, content)
}

fn readFile(path: string): string {
    return __native_read_file(path)
}

🏗️ 2단계의 완성: '구조'의 탄생
작성하신 tree.fl 코드는 이제 단순한 파일 저장을 넘어 **"프로젝트 전체의 형상"**을 관리합니다. 여기서 중요한 포인트는 **Merkle Tree(머클 트리)**의 특성입니다.
 * 데이터 원자화: blob.fl이 파일 내용을 보호합니다.
 * 구조 원자화: tree.fl이 파일의 이름과 위치를 보호합니다.
 * 결과: 최상위 트리의 hash 하나만 알면, 그 하위의 모든 파일 이름, 내용, 폴더 구조가 단 1비트도 변하지 않았음을 기록으로 증명할 수 있습니다.
