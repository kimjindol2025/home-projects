좋습니다. 1단계에서 **'파일 하나(Blob)'**를 지문(Hash)으로 만드는 법을 마스터했으니, 이제 2단계: 폴더 구조를 기록하는 '트리(Tree)' 엔진으로 넘어갑니다.
현실의 폴더 안에는 파일만 있는 게 아니라 다른 폴더도 있죠? 깃허브는 이 복잡한 구조를 **'Tree'**라는 객체로 단 한 줄의 텍스트처럼 관리합니다.
2단계: 여러 파일을 묶는 '트리(Tree)' 객체 구현
2-1. 트리의 개념: "폴더를 파일처럼 바라보기"
트리 객체는 일종의 **'장부'**입니다. 이 장부에는 다음과 같은 정보가 기록됩니다.
 * 파일 모드: (예: 100644는 일반 파일, 040000은 디렉토리)
 * 객체 종류: (blob 인지 tree 인지)
 * 해시값: (1단계에서 만든 그 지문)
 * 이름: (실제 파일명이나 폴더명)
2-2. FreeLang 스타일의 트리 생성 로직 (Pseudo-code)
파일 여러 개가 있는 폴더를 하나의 트리 객체로 만드는 과정입니다.
import hashlib
import os

def create_tree(directory_path):
    tree_entries = []
    
    # 1. 폴더 내의 모든 항목을 스캔
    for item in sorted(os.listdir(directory_path)):
        if item == ".freegit": continue # 우리 저장소는 제외
        
        full_path = os.path.join(directory_path, item)
        
        if os.path.isfile(full_path):
            # 파일이면? 1단계의 Blob 해시를 가져옴
            obj_hash = create_blob(full_path) 
            mode = "100644"
            type_ptr = "blob"
        else:
            # 폴더면? 재귀적으로 다시 트리를 만듦 (재귀의 마법!)
            obj_hash = create_tree(full_path)
            mode = "040000"
            type_ptr = "tree"
            
        # 2. 장부에 한 줄 추가
        tree_entries.append(f"{mode} {type_ptr} {obj_hash}\t{item}")

    # 3. 전체 장부 내용을 하나로 합침
    tree_content = "\n".join(tree_entries).encode()
    
    # 4. 트리 객체도 결국 '객체'이므로 1단계와 똑같이 해싱해서 저장
    header = f"tree {len(tree_content)}\x00".encode()
    final_data = header + tree_content
    tree_hash = hashlib.sha1(final_data).hexdigest()
    
    # (압축 후 .freegit/objects에 저장하는 로직은 Blob과 동일)
    save_to_objects(tree_hash, final_data)
    
    return tree_hash

2-3. 왜 이 단계가 중요한가요? (The Power of Merkle Tree)
이 방식은 머클 트리(Merkle Tree) 구조의 기초가 됩니다.
 * 초고속 비교: 폴더 안에 파일이 100만 개 있어도, 최상위 Tree 해시값 딱 하나만 비교하면 폴더 전체에 변화가 있는지 0.0001초 만에 알 수 있습니다.
 * 재사용: 파일 하나만 바뀌면 그 파일이 포함된 트리의 해시만 바뀝니다. 변하지 않은 다른 파일들과 폴더들은 기존 해시를 그대로 가리키기만 하면 됩니다.
