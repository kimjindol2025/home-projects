### 실제 프로젝트들이 셀프호스팅까지 가는 데 걸리는 시간 (대략)

언어          | 첫 self-hosting까지 걸린 시간 | 참고
--------------|-------------------------------|------
Zig           | ~5~7년 (C++ → Zig → Zig)      | 2016~2020대 초반
Rust          | ~3~4년                        | 2010~2015
Go            | ~2~3년                        | 초기 버전은 C로, 점진적 전환
TCC (Tiny C)  | 몇 달~1년                     | 극도로 작고 단순
CakeML        | 학술 프로젝트라 5년+          | 형식증명까지 포함
**FreeLang**  | **아직 미달성** (tiny 단계)   | 2026년 3월 기준

### FreeLang 프로젝트에서 가장 큰 벽 3개 (현재 기준)

1. **아키텍처 불일치** (x86-64 바이너리 vs ARM64 머신)  
   → QEMU-user-static이나 실제 x86 머신 없이는 v1.elf 실행 자체가 불가능

2. **런타임 부재**  
   → ELF를 실행하려면 최소한 _start, exit, write syscall 등을 FreeLang으로 구현하거나 링크해야 함  
   → 지금은 "ELF는 만들었지만 실행은 못함"

3. **struct 파싱 불가**  
   → JS 단계 파서가 struct를 못 읽으니까, 진짜 컴파일러 소스(complete 버전)는 컴파일 불가  
   → tiny.fl처럼 struct 없는 극소 버전만 가능

### 그래서 셀프호스팅은 "어려운가"?

- **취미/학습/증명 목적** → ★★☆☆☆ (tiny 수준은 충분히 가능)
- **실용적/프로덕션 수준** → ★★★★★ (거의 모든 언어가 2~7년 걸림)
- **완벽한 3-stage bootstrap + 형식증명** → ★★★★★★ (학계 수준, CakeML·CompCert급)

FreeLang 프로젝트는 지금 **"가장 어려운 부분 직전에 와 있다"** 고 볼 수 있어요.  
(v1 ELF는 만들었고, 결정성은 증명했는데, **실행 + 재컴파일 체인**이 아직 안 됨)

### 다음으로 가장 현실적인 한 방 (지금 하면 될 만한 것)

1. QEMU-user-x86_64 설치  
   ```bash
   # Ubuntu/Debian
   sudo apt install qemu-user-static binfmt-support
   sudo update-binfmts --enable qemu-x86_64
   ```

2. v1 실행 시도  
   ```bash
   qemu-x86_64 ./v1-compiler.elf freelang-compiler-tiny.fl > v2-from-qemu.elf
   ```

3. JS로 만든 v2와 비교  
   ```bash
   md5sum v2-from-qemu.elf  # JS로 만든 v2-elf와 같은지 확인
   ```

이게 성공하면 **진짜 self-hosting의 첫 단계**가 되는 거예요.
