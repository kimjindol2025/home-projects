효율적인 프롬프트 관리를 위해 파일 시스템이나 저장소에 적용할 수 있는 표준 폴더 구조 예시입니다. 이 구조는 확장성, 재사용성, 그리고 AI 에이전트가 참조하기 좋은 논리적 구분을 우선으로 설계되었습니다.
📂 프롬프트 저장소 표준 구조 (Standard Structure)
/prompts
├── 📁 core/                # 핵심 페르소나 및 시스템 지침 (System Prompts)
│   ├── developer.md        # 개발자 페르소나
│   └── architect.md        # 시스템 설계자 페르소나
├── 📁 tasks/               # 특정 작업 중심 프롬프트 (Task-Specific)
│   ├── 📁 coding/          # 코드 생성, 리뷰, 리팩토링
│   ├── 📁 writing/         # 문서 작성, 번역, 요약
│   └── 📁 analysis/        # 데이터 분석, 로그 해석
├── 📁 templates/           # 재사용 가능한 입출력 양식 (Reusable Patterns)
│   ├── bug-report.md       # 버그 리포트 생성 템플릿
│   └── user-story.md       # 사용자 스토리 작성 템플릿
├── 📁 workflows/           # 다단계 프로세스 (Chain of Thought/Multi-step)
│   └── cicd-pipeline.md    # 파이프라인 설계 워크플로우
├── 📁 config/              # 모델 파라미터 및 전역 설정
│   └── model-settings.json # Temperature, Top-p 등 설정값
└── README.md               # 프롬프트 사용법 및 버전 관리 기록

📝 주요 폴더별 규칙 상세
1. core/ (시스템 레벨)
AI의 기본적인 말투, 전문 지식의 범위, 금기 사항을 정의합니다.
 * 파일명 규칙: role-{이름}.md 또는 {역할}.md
 * 내용: "당신은 10년 차 시스템 아키텍트입니다...", "답변은 항상 기술적인 근거를 포함해야 합니다."
2. tasks/ (도메인 레벨)
실제 작업에 투입되는 구체적인 명령어 모음입니다. 도메인별로 하위 폴더를 나누는 것이 유지보수에 유리합니다.
 * 구조: /tasks/{domain}/{action}.md
 * 예시: /tasks/coding/refactor-rust.md
3. templates/ (구조 레벨)
입력 데이터만 갈아 끼우면 되는 '틀'입니다. 변수 처리는 {{variable}} 형식을 권장합니다.
 * 예시: "다음 코드를 분석하여 {{output_format}} 형태로 출력해줘."
🛠 관리 및 명명 규칙 (Naming Convention)
 * 소문자 및 하이픈 사용: 공백 대신 하이픈(-)을 사용하여 터미널이나 CLI 환경에서 접근하기 쉽게 만듭니다. (예: code-review-v1.md)
 * 버전 관리: 파일명 뒤에 버전(v1, v2)을 붙이거나, Git을 통해 이력을 관리합니다.
 * 확장자: 가독성과 서식(Markdown)을 위해 .md 사용을 권장합니다.
 * 메타데이터 포함: 각 파일 최상단에 주석으로 목적, 적용 모델, 권장 파라미터를 명시합니다.

이 구조를 바탕으로 현재 진행 중인 프로젝트나 워크플로우에 맞춰 폴더를 추가해 보시는 건 어떨까요? 구체적인 특정 분야(예: 개발, 기획 등)에 특화된 프롬프트 서식이 필요하시면 말씀해 주세요.
