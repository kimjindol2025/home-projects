*✅ Railway.app으로 FreeLang 블로그 배포 가이드 (2026년 최신 기준)**

이제 실제로 배포를 진행할 차례입니다. 아래는 **가장 간단하고 추천하는 방법**으로 정리했습니다.

### 🚀 Railway 배포 단계 (5~10분 소요)

1. **Railway 계정 생성 / 로그인**
   - https://railway.app 접속
   - GitHub 계정으로 로그인 (가장 빠름) 또는 이메일 가입

2. **새 프로젝트 만들기**
   - 대시보드에서 **“New Project”** 또는 **“Start a New Project”** 클릭
   - **Deploy from GitHub Repo** 선택

3. **저장소 선택**
   - FreeLang 블로그가 있는 GitHub 저장소 검색 및 선택
   - Railway가 자동으로 `package.json`을 인식하고 Node.js 프로젝트로 감지합니다.
   - **Deploy Now** 버튼 클릭 (또는 변수 추가 후 Deploy)

4. **배포 설정 확인 (필요 시)**
   - Railway가 자동으로 다음을 감지합니다:
     - `package.json`의 `start` 스크립트 (`npm start`)
     - `Procfile` (web: npm start 등)
     - `Dockerfile` (있으면 우선 사용)
   - 포트: 보통 `PORT` 환경 변수 사용 (기본 3000 또는 8253)
   - 필요하다면 **Variables** 탭에서 환경 변수 추가 (예: `PORT=8253`, `NODE_ENV=production`)

5. **배포 완료 후**
   - 빌드가 끝나면 (보통 1~3분) **배포 URL**이 생성됩니다.
     - 형식: `https://your-project-name.up.railway.app`
   - URL을 클릭해 블로그가 정상 작동하는지 확인하세요.

### ⚠️ 배포 후 반드시 해야 할 작업

**index.html 또는 프론트엔드 설정 변경**

현재 코드에 아래처럼 되어 있을 가능성이 큽니다:
```js
const BACKEND_URL = 'http://localhost:8253';
```

이 부분을 **배포된 실제 URL**로 바꿔야 합니다.

예시:
```js
const BACKEND_URL = 'https://freelang-blog.up.railway.app';   // ← 여기에 실제 URL 입력
```

변경 후:
- GitHub에 다시 푸시 → Railway가 **자동 재배포**됩니다. (GitHub 연동 시)

### 추가 팁
- **자동 배포**: GitHub에 푸시할 때마다 Railway가 자동으로 빌드·배포합니다.
- **로그 확인**: Railway 대시보드에서 실시간 로그와 배포 히스토리를 볼 수 있습니다.
- **도메인 연결**: 나중에 커스텀 도메인(예: blog.freelang.dev)을 연결하고 싶으면 Settings → Domains에서 설정 가능
- 문제가 발생하면 Railway Logs 또는 Build Logs를 먼저 확인하세요.
