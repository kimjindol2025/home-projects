문제 A — range(3) → 0 무한반복

예상: 0, 1, 2 출력
실제: 0, 0, 0, 0, 0 ... (무한반복)

원인 추정:
루프 카운터 변수가 매 반복마다 
초기값으로 리셋되고 있음

전형적인 패턴:
  LOAD_CONST 0     ← 루프 시작할 때마다 i=0으로 재초기화
  STORE_VAR i      ← 이게 루프 본문 안에 잘못 배치됨
  LOAD_VAR i
  CALL range ...

확인할 IR 출력:
IR 덤프 명령으로 실제 생성된 IR 확인
python3 main.py dump examples/03_loop_and_list.pf

또는 디버그 플래그
python3 main.py run --debug examples/03_loop_and_list.pf

예상 올바른 IR vs 잘못된 IR:
✅ 올바른 IR              ❌ 잘못된 IR
─────────────────         ─────────────────
LOAD_CONST 0              LOOP_START:
STORE_VAR i    ← 루프 밖    LOAD_CONST 0
LOOP_START:                 STORE_VAR i   ← 루프 안!
  LOAD_VAR i                LOAD_VAR i
  LOAD_CONST 3              ...
  JUMP_IF_GE END
  ...
  LOAD_VAR i
  LOAD_CONST 1
  BINARY_ADD
  STORE_VAR i   ← 증가
JUMP LOOP_START
END:

문제 B — 배열 변수 루프 → 타임아웃

이 패턴에서 타임아웃 발생
arr = [1, 2, 3]
for x in arr:    ← len(arr) CALL 실패
    print(x)

원인 추정:
len() 함수가 배열 객체를 받지 못하거나
반환값을 루프 조건으로 연결하지 못함

VM 내부에서:
  CALL len, [arr]  → 결과가 NaN or undefined
  루프 종료 조건이 항상 False
  → 무한루프 → 타임아웃

from ir_gen import IRGenerator
from parser import Parser
from lexer import Lexer

src = '''
for i in range(3):
    print(i)
'''
tokens = Lexer(src).tokenize()
ast = Parser(tokens).parse()
ir = IRGenerator().generate(ast)
for i, instr in enumerate(ir):
    print(i, instr)
"

🛠️ 예상 수정 위치

파일: ir_gen.py (또는 codegen.py)
함수: visit_ForStmt() 또는 generate_for_loop()

현재 문제 있는 코드 패턴:
def visit_ForStmt(self, node):
❌ 초기화가 루프 안에 있을 가능성
    self.emit('LOOP_START')
    self.emit('LOAD_CONST', 0)      ← 여기가 루프 안
    self.emit('STORE_VAR', node.var)

수정 방향:
def visit_ForStmt(self, node):
✅ 초기화는 루프 밖에
    self.emit('LOAD_CONST', 0)      ← 루프 밖으로 이동
    self.emit('STORE_VAR', node.var)
    loop_start = self.new_label()
    self.emit('LABEL', loop_start)
    ...
