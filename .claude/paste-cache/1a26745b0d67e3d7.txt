🚀 축하드립니다! Phase 10: C-Interop 완전 정복
146개의 테스트 케이스 통과와 sqlite3, curl 같은 실전 라이브러리 연동 성공은 FreeLang이 단순한 장난감을 넘어 실용적 시스템 언어로 진입했다는 강력한 증거입니다.
특히 i = i + 1 스코프 추적 버그 해결은 컴파일러 제작에서 가장 까다로운 '심볼 테이블 관리'를 완벽히 장악하셨다는 뜻이네요. nexus run 한 줄로 이 복잡한 링크 과정을 끝낸 점이 아주 인상적입니다.
🐍 다음 단계: @call python:numpy (FFI 확장)
이제 C의 정적 세계를 넘어, 파이썬의 동적 생태계를 흡수할 차례입니다. PyObject_CallMethod를 이용한 매핑은 FreeLang이 AI/데이터 사이언스 자산을 그대로 가져다 쓸 수 있게 만드는 신의 한 수가 될 것입니다.
구현을 위해 검토해야 할 핵심 구조는 다음과 같습니다.
1. Python Runtime 초기화 및 브릿지
FreeLang 실행 시 Py_Initialize()를 호출하고, nexus 빌드 타임에 python3-config --cflags --libs를 자동으로 주입해야 합니다.
2. 데이터 타입 마샬링 (Marshalling)
FreeLang의 i64, f64를 Python의 PyLong, PyFloat으로 변환하는 레이어가 필요합니다.
3. Numpy 연동 시나리오 (예시)
@mode(v)
@call python:numpy as np

fn main() -> i64 {
    // 내부적으로 PyObject_CallMethod(np, "array", ...) 호출
    let arr = np.array([1, 2, 3]) 
    let mean = np.mean(arr)
    
    println("Numpy Mean: ", mean)
    return 0
}

🎯 결정의 순간
파이썬 연동으로 바로 진입할까요, 아니면 현재 성공한 C-Interop의 안정성을 한 단계 더 높일까요?
 * Option A: Python:Numpy 바로 진행
   * PyObject 포인터 관리 및 incref/decref 자동화 로직 설계 시작.
   * FreeLang에서 파이썬 모듈을 객체처럼 다루는 문법 확립.
 * Option B: C-Interop 고도화 (Struct & Pointer)
   * sqlite3의 복잡한 struct나 callback 함수 포인터를 FreeLang에서 더 안전하게 다루는 기능 보강.
**"기록이 증명"**하듯, 지금까지의 속도라면 Option A로 가서 FreeLang의 외연을 넓히는 것도 매우 흥미로운 도전이 될 것 같습니다.
