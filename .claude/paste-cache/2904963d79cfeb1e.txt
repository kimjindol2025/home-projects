fetch()           // Go 패키지 호출
      println(arr + num)
  }
  ```
  → FreeLang이 자동으로 FFI/포팅 → 통합 C 바이너리 생성 → polyglot-poc에서 성능 비교까지!

이게 바로 **FLIR v1.0**의 실체예요. (너가 이미 FREELANG_ECOSYSTEM_PLAN.md에 써놓은 그 비전)

### 현실적으로 어떻게 구현할까? (단계별 로드맵)

**Phase 버스정류장 1.0 (이번 주 목표 – MVP)**
1. FreeLang syntax에 **라이브러리 호출 문법** 추가  
   ```free
   @call python:numpy
   @call rust:rand 0.1.0
   @call go:github.com/gin-gonic/gin
   ```
   → parser.ts에 `@call` 토큰 + import-like AST 노드 추가 (이미 for-in 추가한 스타일로 1시간 컷 가능)

2. FLIR(중간 표현) 단계에서 **포팅 규칙** 정의  
   - Python 라이브러리 → Cython + FreeLang FFI stub 생성  
   - Rust → cargo → C ABI export  
   - Go → cgo 또는 tinygo  
   → codegen.ts에서 각 언어 별 “버스 승차” 코드 생성 (현재 C 코드젠 로직 확장)

3. polyglot-poc backend에 **버스 정류장 라우터** 추가  
   - Editor에서 FreeLang 선택 → nexus 호출 → 라이브러리 자동 install (Docker sandbox 안에서) → 통합 컴파일 → 성능 비교

**Phase 버스정류장 2.0 (다음 1~2주)**
- 실제 런타임 embed  
  - Python: PyBind11 or C API  
  - Rust: cbindgen  
  - Go: cgo  
  - Julia: Julia C API  
- 하나의 바이너리에 **모든 언어 런타임** 포함 (GraalVM Native Image 스타일)

**최종 목표 (1개월 내)**
FreeLang 한 파일로 **10개 언어 라이브러리 동시 호출** → polyglot-poc에서 “버스별 도착 시간(성능)” 비교 차트까지!
