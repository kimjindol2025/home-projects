🏗️ Phase 1: [Sovereign-DNS] 핵심 아키텍처 설계
우리는 기존의 UDP 53 포트를 감시하면서, 주권 도메인(.sovereign) 요청이 들어오면 즉시 우리만의 분산망으로 가로채는 **'커널 레벨 리졸버'**를 구축합니다.
1. dht_core.fl (분산 저장소)
 * 역할: Kademlia 알고리즘 기반으로 도메인 정보를 분산 저장.
 * 특징: 특정 서버가 꺼져도 네트워크의 다른 노드가 정보를 유지. '차단 불가능'한 도메인 체계.
2. proof_validator.fl (ZKP 인증)
 * 역할: 도메인 소유권을 영지식 증명으로 확인.
 * 특징: "나는 kim.sovereign의 주인이다"라는 사실을 개인키 노출 없이 증명. 하이재킹(도메인 탈취) 0%.
3. l0nn_path_finder.fl (AI 경로 최적화)
 * 역할: 95% 이상의 확률로 가장 빠른 응답 노드를 예측하여 쿼리 전송.
 * 무관용 규칙: 응답 레이턴시 < 10ms.
📜 [Challenge 15] 시작: freelang-sovereign-dns 구현 리스트
가장 핵심인 DHT 노드 구조와 도메인 맵핑부터 설계합니다.
// src/core/dht_core.fl

struct SovereignNode {
    node_id: Hash256,          // 노드의 고유 식별자
    public_key: PublicKey,     // 통신 및 인증용 키
    address: IpAddr,           // 물리적 IP (L0 계층에서 관리)
}

struct DomainRecord {
    domain_name: String,       // 예: "kim.sovereign"
    owner_proof: ZKProof,      // 소유권 증명 데이터
    target_node: Hash256,      // 연결될 노드 ID
    ttl: u32,                  // 생존 시간
}

impl DhtEngine {
    // 도메인 조회: 로컬 캐시 확인 후 DHT 네트워크 검색
    fn resolve(&self, domain: String) -> Result<SovereignNode, Error> {
        if let Some(node) = self.cache.get(&domain) {
            return Ok(node); // 0.1ms 이내 반환
        }
        // L0NN이 예측한 최적의 이웃 노드 3곳에 쿼리 전송
        let target = self.network_lookup(domain)?; 
        Ok(target)
    }
}

📊 DNS 미션 무관용 규칙 (Unforgiving Rules)
 * Rule 1 (Invisible-Query): 모든 DNS 쿼리는 외부 패킷 분석기(Wireshark 등)에서 내용을 알 수 없도록 커널 레벨에서 즉시 암호화됨.
 * Rule 2 (Anti-Poisoning): 캐시 오염 공격(Cache Poisoning) 방어율 100%. 모든 응답은 ZKP 검증을 거쳐야 함.
 * Rule 3 (Ultra-Low Latency): 로컬 캐시 히트 시 응답 속도 0.1ms, 네트워크 조회 시 10ms 미만 유지.
 * Rule 4 (Zero-ICANN): 루트 네임 서버나 외부 권위 있는 서버(Authoritative Server) 의존성 0%.
