여기서부터는 “완성”이 아니라 **“확장 방향을 어디로 잡느냐”** 단계라서, 선택이 굉장히 중요합니다. 지금 상태(v1.0.0)는 이미 “언어 코어 + 실행기 + WASM + FFI”까지 갖춘 꽤 강한 기반이에요. 즉, 이제는 **기술이 아니라 전략**입니다.

아래 4가지 방향 중 하나를 고르는 걸 추천합니다 — 각각 성격이 완전히 다릅니다.

---

# 1) 🔥 “사용 가능한 언어”로 가기 (DX + 툴링)
> 👉 가장 추천 (현실적으로 성공 확률 높음)

지금 빠진 건 기능이 아니라 **사용성**입니다.

### 핵심 추가
- LSP (Language Server Protocol)
  - 자동완성
  - go-to-definition
  - hover 타입 표시
- 에러 메시지 개선 (이거 매우 중요)
- 패키지 매니저 (간단한 거라도)
- formatter / linter

### 이유
- 지금 상태는 “엔진 완성”
- 이걸 “개발자가 쓰는 언어”로 바꾸는 단계

👉 이 루트 타면:
> “혼자 만든 언어” → “남도 써볼 수 있는 언어”

---

# 2) ⚡ 성능 특화 (LLVM / JIT / 최적화)
> 👉 기술적으로 제일 재밌는 루트

### 방향
- LLVM backend 붙이기
- IR 최적화 패스
- JIT 실행 (interpreter → JIT)

### 이미 있는 강점
- Codegen 있음
- WASM 있음 → IR 설계 경험 있음

### 추가하면 좋은 것
- escape analysis
- inline expansion
- constant folding 강화

👉 이 루트 타면:
> “취미 언어” → “성능 실험 플랫폼”

---

# 3) 🌐 WASM 중심 플랫폼화 (지금 흐름 이어가기)
> 👉 지금 momentum 가장 자연스럽게 이어짐

이미 한 것:
- WAT 생성
- wasm 바이너리 실행
- Node.js 연동

### 다음 단계
- WASI 지원
- 브라우저 실행 (JS glue)
- sandboxed plugin 시스템
- “이 언어 = WASM용 DSL” 포지셔닝

### 강력한 아이디어
- `@lang` + WASM = polyglot runtime

👉 이 루트 타면:
> “언어” → “플랫폼”

---

# 4) 🧠 언어 자체 진화 (타입 시스템 / 문법 혁신)
> 👉 연구/철학 루트

### 가능 방향
- Hindley–Milner 타입 추론
- trait / interface 시스템
- pattern matching 확장
- effect system (고급)

### 위험
- 시간 많이 듦
- 사용자 가치가 늦게 나옴

👉 이 루트 타면:
> “엔지니어링” → “언어 설계자”

---
