Kim님, 안드로이드의 그늘을 벗어나 이제 **'디지털 신원(Identity)'**의 핵심인 메일 서버를 정복할 시간이군요. 중앙 서버(Gmail, Outlook)에 의존하지 않고, 당신의 나노 커널 위에서 직접 돌아가는 **[Project Sovereign-Mail: Black-Box]**의 설계를 즉시 시작하겠습니다.
이 시스템은 기존의 취약한 SMTP를 최소화하고, 우리만의 **FL-Signal(P2P)**을 메인 통신로로 사용합니다.
🏗️ Phase 1: [Sovereign-Mail] 설계 아키텍처
우리는 총 4개의 핵심 모듈을 구축합니다.
1. mail_encryptor.fl (L0 암호화 엔진)
 * 역할: 메일 본문과 첨부파일을 작성 즉시 AES-256-GCM으로 암호화.
 * 특징: Sovereign-FS의 CAS(Content-Addressable Storage)와 연동하여 동일한 내용의 메일은 단 한 번만 저장(중복 제거).
2. p2p_postman.fl (분산 라우팅)
 * 역할: 고정된 IP 서버 없이, 상대방의 Public Key만으로 메일을 전달.
 * 특징: DHT(Distributed Hash Table)를 통해 수신자의 노드 위치를 파악하고 FL-Signal로 직접 쏩니다.
3. sentry_filter.fl (AI 스팸 방어)
 * 역할: L0NN을 사용하여 메일 헤더의 위조 여부와 본문의 악성 패턴을 10µs 내에 스캔.
 * 무관용 규칙: 오탐률 < 0.01%.
4. mail_vault.fl (격리 저장소)
 * 역할: 메일 데이터를 하이퍼바이저 수준에서 격리된 영역에 보관.
📜 [Challenge 14] 시작: freelang-mail-server 구현 리스트
가장 먼저 구축해야 할 메일 암호화 및 저장 구조부터 설계합니다.
// src/core/mail_vault.fl (예시 구조)

struct MailHeader {
    sender_key: PublicKey,     // 발신자 주권 키
    timestamp: u64,
    subject_hash: Hash256,     // 제목도 암호화
    nonce: [u8; 12],
}

struct MailBox {
    owner: UserID,
    storage_root: Path,        // Sovereign-FS 연결점
}

impl MailBox {
    // 메일 저장: CAS 기반으로 중복 없이, 암호화되어 저장됨
    fn seal_and_store(&self, raw_mail: Vec<u8>) -> Result<MailID, Error> {
        let encrypted = L0Crypto::encrypt(raw_mail, self.master_key)?;
        let mail_id = SovereignFS::push_chunk(encrypted)?; // CAS 저장
        Ok(mail_id)
    }
}

📊 이번 미션의 무관용 규칙 (Unforgiving Rules)
 * Rule 1 (Zero-Plaintext): 커널 메모리 상에 메일 평문이 머무는 시간은 1ms 미만이어야 함.
 * Rule 2 (Serverless): 중앙 DNS 서버 없이 오직 P2P로만 메일 송수신 성공률 99% 달성.
 * Rule 3 (Instant-Scan): L0NN 필터의 메일 분석 속도는 통당 15µs 이하여야 함.
 * Rule 4 (Independence): 외부 라이브러리(OpenSSL 등) 사용 금지, 100% FreeLang 자체 구현.
