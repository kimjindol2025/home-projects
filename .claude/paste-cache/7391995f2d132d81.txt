  C. 파서 (parser.fl: 200줄+)

  지원되는 문법:
  program   → stmt*
  stmt      → let_stmt | fn_stmt | if_stmt | while_stmt
  | return_stmt | expr_stmt
  let_stmt  → "let" ident "=" expr
  fn_stmt   → "fn" ident "(" params? ")" ":" type "{"
  stmt* "}"
  if_stmt   → "if" expr "{" stmt* "}" ("else" "{" stmt*
  "}")?
  while_stmt → "while" expr "{" stmt* "}"
  expr      → binary | unary | primary | call
  binary    → expr
  ("+"|"-"|"*"|"/"|"=="|"!="|"<"|"<="|">"|">=") expr

  4️⃣  강점 & 약점

  ✅ 강점

  1. 자기 참조 (Self-hosting): FreeLang 컴파일러를
  FreeLang으로 작성
  2. 깔끔한 구조: Lexer → Parser → Codegen의 명확한 단계
  3. C로 생성: 고성능 실행 파일 생성 가능
  4. 패턴 매칭: Codegen에서 match 식으로 깔끔한 표현식
  처리
  5. 타입 안전성: 런타임에 태그 기반 타입 추적

  ⚠️  약점

  1. 제한된 문법:
    - 제네릭 미지원
    - 클로저 미지원 (선언만 가능)
    - 사용자 정의 enum 미지원
    - 구조체 필드 이니셜라이저 부분 구현
  2. 에러 처리:
    - parser_expect()에서 오류 발생 시 EOF 토큰 반환
  (프로그래밍 오류)
    - 에러 메시지 출력 없음
  3. 생성 C 코드 품질:
    - 매개변수 없는 함수만 생성 (fn_stmt 라인 145:
  fl_value " + name + "() {)
    - 함수 파라미터 무시됨
    - 반환값 타입 무시됨
  4. 메모리:
    - 단순 malloc/free (GC 없음, 메모리 누수 가능)
    - 대용량 데이터 처리 부담
  5. 표현식:
    - 배열 리터럴 [1, 2, 3] 생성만 하고 요소 미포함
  (라인 121)
