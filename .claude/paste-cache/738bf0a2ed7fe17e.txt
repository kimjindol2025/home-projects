좋다.
질문 수준이 이제 구조 설계 검증 단계다. 바로 간다.

1️⃣ Embedding 64차원 vs Vocab 1,940개

결론: 64는 “작은 실험용”, 제품급은 아님.

경험적으로:

vocab ~2k

d_model 64 → 장난감 / 구조 검증용

d_model 128 → 최소 실전 베이스라인

d_model 256 → 구조 표현력 안정권


왜 64가 작냐면

Embedding은 사실상

> “토큰 → 개념 벡터 공간 좌표”



64차원은:

타입 정보

스코프 정보

문법 위치

의미적 패턴


이걸 동시에 담기엔 압축률이 너무 높다

특히 FreeLang처럼:

코드 구조

타입 시스템

키워드 다양성


이 있는 언어는 128 이상이 급격히 안정화되는 구간일 가능성 높음.

📌 추천 실험:

dim    train loss    val loss    ppl

64    ?    ?    ?
128    ?    ?    ?
256    ?    ?    ?


이건 이론이 아니라 측정 문제다.

2️⃣ Attention을 아직 안 붙였다?

이건 지금 구조가 사실상:

> "Context-less bigram-ish model"



에 가까울 가능성이 높다.

Self-Attention을 붙이지 않으면:

장거리 의존성 학습 불가

함수 시작 ↔ 끝 매칭 불가

중첩 구조 약함

타입 전파 이해 못함


붙이는 타이밍

정답은:

> embedding dim 확정 → attention 붙임 → FFN 확장 → layer stacking



지금 64로 attention 붙이면
capacity 부족 + gradient 불안정 나올 가능성 있음.

추천 순서:

1. dim 128으로 올림


2. single-head attention 1 layer


3. train curve 확인


4. multi-head 확장

3️⃣ 실행 가능한 코드 비율

이건 굉장히 중요한 질문이다.

4,046 파일 중:

완전 실행 가능: ?

컴파일만 됨: ?

syntax 오류: ?

타입 오류: ?


만약:

> 30% 이상이 깨진 코드



라면 학습은 이렇게 된다:

모델이 “에러 패턴”을 학습함.

하지만 재미있는 건:

LLM은 오히려 에러 데이터도 학습 가치가 있음
→ "에러를 수정하는 패턴"을 배우기 때문.

문제는:

실행 불가 코드가 너무 많으면

문법 안정성이 흔들림


📌 반드시 해야 할 것:

FL 파일 전체 컴파일 돌려서
- success
- syntax fail
- type fail
- runtime fail
통계 뽑기

이건 모델 이전에 데이터 검증 단계다.

4️⃣ 한글 MD + FL 코드 동일 토크나이저

이건 꽤 미묘하다.

같이 학습하면 좋은 점

주석 이해력 증가

문서 ↔ 코드 매핑 능력 생김

자연어 설명 → 코드 생성 가능성 증가


단점

토큰 분포 왜곡

한글 빈도 때문에 코드 토큰 학습이 희석될 수 있음


특히 vocab 1,940 수준이면
한글 + 코드가 공간을 공유하면서 표현력이 줄어들 가능성 있음.
