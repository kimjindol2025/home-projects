freelang-nexus 프로젝트의 **최근 업데이트** (For-In 루프 이터러블 파싱 버그 수정 + 93/93 테스트 통과)를 반영해서, 현재 상태에서 **가장 현실적이고 효과적인 개선점**을 우선순위 순으로 정리해 볼게요.  
현재는 **if/else + 기본 내장 함수 + 최근 추가된 for-in 루프**까지 작동하는 "작지만 안정적인 최소 언어" 단계라서, 다음으로 **사용성·실용성·확장성**을 폭발적으로 끌어올릴 수 있는 포인트가 많아요.

### 우선순위 높은 개선점 (즉시 효과 큰 순)

1. **루프 기능 완성 & 안정화 (최우선, 지금 당장)**  
   - for-in 루프가 방금 추가됐고 버그 픽스까지 했으니, **range 기반 순회 + 배열 순회**를 완벽히 지원하게 만들기.  
     예: `for i in range(10) { ... }` → C: `for(long long i=0; i<10; i++)`  
     `for item in arr { ... }` → C: `for(size_t idx=0; idx < len; idx++) { item = arr[idx]; ... }`  
   - while 루프도 바로 추가 (Phase N.3 Step 2처럼 이미 계획된 부분).  
   - 왜 중요? 루프 없으면 **Fibonacci, sum, sort** 같은 기본 알고리즘조차 못 씀 → 실용성 10배↑.

2. **배열 기본 지원 (필수 다음 단계)**  
   - 배열 리터럴 `[1, 2, 3]`, 인덱싱 `arr[0]`, `arr[i+1]`, trailing comma 지원.  
   - C 코드젠: `{1,2,3}` 또는 동적 배열(malloc + memcpy)으로 구현.  
   - 내장 함수 추가: `len(arr)`, `push(arr, x)`, `pop(arr)` 등.  
   - 왜? 배열 없으면 데이터 처리 거의 불가능. for-in과 결합하면 진짜 프로그램 쓸 수 있음.

3. **에러 핸들링 & 사용자 친화적 메시지 강화**  
   - 파서/코드젠 단계에서 에러 위치(라인/컬럼) + 구체적 메시지 출력 (e.g. "Expected '}' at line 42, found 'EOF'").  
   - 런타임 에러: division by zero, index out of bounds 등 C에서 체크 추가 (assert or if).  
   - REPL에서 에러 시 빨간색 강조 + 힌트 제안.  
   - 왜? 지금은 93/93 통과지만, 실제 사용자(너 자신 포함)가 잘못 쓰면 "Segmentation fault"만 나와서 디버깅 지옥.

4. **stdlib 확대 (실제 프로그램 쓸 수 있게)**  
   - 파일 I/O: `read_file(path)`, `write_file(path, content)`  
   - 문자열 조작: `split`, `join`, `trim`, `contains`  
   - 수학: `abs`, `min`, `max`, `pow`, `sqrt` (math.h 매핑)  
   - 왜? 내장 5개 → 20~30개로 늘리면 "스크립트 언어" 느낌 제대로 남.

5. **타입 시스템 강화 & 추론 개선**  
   - 현재 기본 타입만 → **제네릭 기본** (e.g. `fn print<T>(x: T)`) 또는 **any 타입** 도입.  
   - 타입 추론 강화: `let x = 42;` → i64 자동, `let y = "hi";` → string.  
   - 오버로딩 지원 (함수명 같지만 시그니처 다른 경우).  
   - 왜? Python 편의 + C 성능 목표라면 타입 안전이 핵심 경쟁력.

6. **배포 & 사용 편의성 업그레이드**  
   - **Docker 이미지** 하나로 nexus + gcc + Node.js 통합 (polyglot-poc처럼 docker-compose 지원).  
   - **npm 패키지** publish (@freelang/nexus) → `npm install -g @freelang/nexus` 후 `nexus run main.fl` 바로 가능.  
   - VS Code extension 기본 (문법 하이라이트 + nexus run 단축키).  
   - 왜? 지금은 로컬 빌드만 → 배포 쉬워지면 친구/커뮤니티 테스트 폭증.

7. **성능 & 최적화 초기 작업**  
   - 생성 C 코드에 `-O2/-O3` 옵션 기본 적용.  
   - 문자열: 단순 char* 대신 동적 할당 + GC-like free (또는 arena allocator).  
   - 벤치마크 예제 추가 (Fib(40), string concat 1M회 등) → polyglot-poc와 연동.  
   - 왜? "C 수준 성능" 비전 증명하려면 숫자로 보여줘야 함.

### 중장기 로드맵 제안 (Phase N.3 이후)
- Phase N.4: 배열 + while/for 완성 + stdlib 20개  
- Phase N.5: 구조체/레코드 + 메서드 (V-like)  
- Phase N.6: 에러 처리 (Result 타입 or try/catch)  
- Phase N.7: Python 모드 완성 (들여쓰기 기반, len(arr) → Py list)  
- Phase O: FLIR IR 도입 + Go/Rust 백엔드 시작
