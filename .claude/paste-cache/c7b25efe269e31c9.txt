**kim/polyglot-poc.git** 저장소의 개선점은 이전 README와 로그(Phase N.2 100% 선언, Docker, CI/CD, 5개 핵심 언어 중심) 기반으로 분석하면, **현재 상태가 "매우 잘 포장된 PoC → 실사용 가능한 데모 툴"** 단계라서 다음 레벨로 끌어올릴 포인트가 명확해요.  
(저장소가 private/self-hosted라 직접 접근 불가하지만, 제공된 이전 정보 + 최근 패턴으로 현실적으로 정리)

### 우선순위 높은 개선점 (즉시 효과 큰 순, 2026년 3월 기준)

1. **지원 언어 실제 완성도 높이기 (가장 급함, 핵심 가치)**  
   - 현재 README: C, Python(Cython), Go, Rust, TypeScript 5개 "✅✅✅/✅" 선언, 하지만 Java/Kotlin은 JVM이라 C 통합 불가 → "❌ 미지원" 명시.  
   - WASM, FV-Julia, FreeLang도 "계획/부분" 단계.  
   - **개선 제안**:  
     - 5개 핵심 언어만 집중 → 완벽한 작동 증명 (e.g. benchmarks/rust_benchmark.rs처럼 각 언어당 10+ 벤치마크 케이스 추가).  
     - FreeLang 통합 강화: freelang-nexus에서 생성된 C 코드를 polyglot에서 바로 컴파일/비교 가능하게 연동 (cross-repo script 추가).  
     - WASM 지원 실제 구현 (emcc → C 통합) – 웹 브라우저 내 실행으로 차별화.  
   - 효과: "10개 언어" → "5개 완벽 + 2개 추가" 로 신뢰도 ↑.

2. **보안 & 안전 실행 환경 강화 (프로덕션 데모 필수)**  
   - 임의 코드 exec (gcc, go build, rustc 등) → 보안 홀 엄청남 (코드 인젝션, 무한 루프, 파일 삭제 등).  
   - **개선 제안**:  
     - Docker-in-Docker or gVisor/Firejail 같은 샌드박스 적용 (각 컴파일을 isolated 컨테이너에서).  
     - 타임아웃(5~10초) + 메모리/CPU 제한 (ulimit or cgroup).  
     - 입력 크기 제한 (50KB → 10KB로 줄이기) + dangerous syscall 블록.  
     - 에러 시 "Sandbox violation" 메시지 + 로그 숨김.  
   - 효과: 공개 데모 사이트 올릴 때 해킹/악용 방지 → 실제 공유 가능.

3. **Frontend UX & 기능 확대 (사용자 끌어들이기 핵심)**  
   - 현재 Editor + Comparison 페이지 좋지만, 아직 기본적.  
   - **개선 제안**:  
     - Monaco Editor 통합 (VS Code 스타일 문법 하이라이트, 자동완성 – 각 언어 extension 로드).  
     - 실시간 미리보기 (코드 변경 시 auto-compile debounce).  
     - 코드 공유/링크 생성 (URL에 코드 해시 or Gist-like 저장).  
     - 다크/라이트 모드 + 반응형 모바일 지원 강화.  
     - 리더보드: 사용자 제출 벤치마크 랭킹 (anonymous).  
   - 효과: "재미있는 툴" → "사람들이 계속 오는 사이트" 로 전환.

4. **CI/CD & 배포 자동화 완성 (유지보수성)**  
   - 이미 Gitea Actions + Docker + k8s yaml 언급 있지만, 실제 작동 여부 미지수.  
   - **개선 제안**:  
     - CI에서 각 언어 컴파일러 설치/버전 체크 + 벤치마크 자동 실행 → 실패 시 알림.  
     - 자동 배포: 태그 푸시 시 Docker Hub/ECR 푸시 + Cloud Run/ECS deploy.  
     - Monitoring: Prometheus + Grafana or 간단 health endpoint + UptimeRobot.  
   - 효과: "혼자 관리" → "장기 운영 가능" 단계.

5. **성능 비교의 공정성 & 신뢰도 업그레이드**  
   - 현재 Fibonacci 등 5개 예제 중심 → 편향 가능.  
   - **개선 제안**:  
     - 벤치마크 세트 확대: String 1M concat, Matrix mul(100x100), Prime sieve(1M), JSON parse/serialize 등 10+ 카테고리.  
     - Warm-up run + multiple iterations (평균/표준편차 표시).  
     - 메모리/CPU/바이너리 크기 + compile time 모두 표기.  
     - "C 기준 1.0x" 정규화 + 차트에 로그 스케일 옵션.  
   - 효과: "진정한 공정 비교" 비전 증명 → 논문/블로그 포스팅 재료.

6. **문서 & 온보딩 개선**  
   - README_FINAL.md 등 잘 돼 있지만, 초보자용 가이드 부족.  
   - **개선 제안**:  
     - Quick Start 비디오 (1분 Loom or GIF).  
     - CONTRIBUTING.md + Good First Issue 라벨링.  
     - API docs (Swagger/OpenAPI or Redoc).  
     - 영어 README 완전 번역 + 한국어/영어 토글.  
   - 효과: 외부 기여/사용자 유입 ↑.

### 요약: 지금 가장 급한 3가지 (1~2주 안에 끝낼 수 있는 수준)
1. **보안 샌드박스** 도입 → 공개 데모 안전하게  
2. **Monaco + 실시간 compile** → UX 폭발  
3. **FreeLang/WASM 실제 연동** + 벤치마크 10개 추가 → "polyglot" 이름값 제대로

이 3개만 해도 **PoC → 진짜 유용한 오픈소스 툴** 로 점프할 거예요.  
polyglot-poc가 freelang-nexus의 "쇼케이스" 역할을 제대로 하려면, nexus에서 만든 FreeLang 코드가 polyglot에서 바로 비교되는 흐름이 제일 강력한 스토리일 듯!
