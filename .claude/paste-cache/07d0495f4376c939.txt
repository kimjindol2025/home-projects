**Zig 컴파일러 완전 분해 + 구현 로드맵** (2026년 기준, 0.15+ self-hosted 기준)

너가 “분해할거야”라고 한 거 보니, **소스코드 직접 뜯어서 구조 파악 → 완전 재구현** 목표인 것 같아서, **실제 Zig 팀이 쓰는 파이프라인 + src 구조 + 단계별 구현 방법**까지 완전 정리해줄게.  
Zig 컴파일러는 **오픈소스**라 바이너리 리버스할 필요 없이 바로 소스 뜯으면 된다. (GitHub에서 Codeberg로 완전 이전됨)

### 1. 공식 저장소 & 빌드 (제일 먼저 해라)
```bash
git clone https://codeberg.org/ziglang/zig.git
cd zig
zig build   # self-hosted로 빌드됨 (LLVM 의존 없이도 가능)
```
- `src/` 폴더가 **진짜 컴파일러 본체**다.
- bootstrap은 이제 거의 안 쓰고, self-hosted가 기본.

### 2. Zig 컴파일러 파이프라인 (이게 핵심 분해 포인트)

```
Tokenize → Parse → AstGen → Sema → Codegen → Link
```

| 단계          | 입력          | 출력          | 주요 파일 (src/)                  | 하는 일 |
|---------------|---------------|---------------|-----------------------------------|--------|
| **Tokenize**  | .zig 소스     | Token 리스트  | Parser.zig 내부                   | lexing |
| **Parse**     | Token         | AST           | Ast.zig, Parser.zig               | 문법 트리 |
| **AstGen**    | AST           | ZIR           | AstGen.zig (또는 std/zig 내부)    | untyped bytecode-like IR (파일 단위) |
| **Sema**      | ZIR           | AIR           | **Sema.zig** (최대 난이도)        | 타입 체크 + comptime 실행 + error set 등 |
| **Codegen**   | AIR           | Machine Code  | **codegen/** (x86_64.zig, aarch64 등) | 백엔드 (LLVM / self-hosted MIR) |
| **Link**      | Object        | 실행파일      | link/                             | LLD 스타일 링커 |

**중요 IR 2개**
- **ZIR** (Zig Intermediate Representation): untyped, 파일 전체
- **AIR** (Analyzed Intermediate Representation): typed + comptime 끝난 상태, 함수 단위

### 3. src/ 주요 디렉토리 분해 (2026년 master 기준)
```
src/
├── Air.zig              ← AIR instruction 정의 (제일 중요)
├── Sema.zig             ← semantic analysis 핵심 (여기부터 뜯어라)
├── Zcu.zig              ← Zig Compilation Unit (전체 프로젝트 관리)
├── Compilation.zig      ← 빌드 전체 orchestrator
├── codegen/             ← 백엔드들 (x86_64, aarch64, riscv64, wasm 등)
├── link/                ← 링커
├── Package.zig          ← 모듈/패키지 시스템
├── Ast.zig              ← AST
├── Zir.zig              ← ZIR
├── Parser.zig           ← 파서
└── AstGen.zig           ← AST → ZIR
```

**추천 공부 순서 (실제로 Zig 팀 멤버들이 추천하는 순서)**
1. `Air.zig` 읽기 (instruction이 어떤 구조인지)
2. `Sema.zig`의 `analyzeBodyInner`, `analyzeFnBody` 함수
3. `codegen/x86_64.zig` (self-hosted 백엔드 예시)
4. `Zcu.zig` + `Compilation.zig`

### 4. 완전 구현 로드맵 (0부터 100까지)

**Phase 0: 준비 (1주)**
- Zig Language Reference 전부 읽기 (master 문서)
- toy compiler 만들기 (계산기 언어 정도로)

**Phase 1: Frontend (1~2개월)**
```zig
// 목표: .zig 파일 → ZIR까지
fn tokenize() ...
fn parse() Ast ...
fn astGen(ast: Ast) Zir ...
```
- Zig parser는 hand-written recursive descent라 따라하기 쉽다.
- AstGen까지 만들면 “Zig-like 언어”가 된다.

**Phase 2: Sema (제일 어렵고 중요, 3~6개월+)**
이게 Zig의 핵심 (comptime + error set + generic).
- `Sema`는 ZIR을 읽으면서 **실제 실행**처럼 돌린다 (comptime interpreter 내장).
- 먼저 **runtime-only** 버전 만들고, 나중에 comptime 추가.
- AIR instruction 하나씩 매핑하면서 구현.

**Phase 3: Backend (2~4개월)**
3가지 선택지:
1. **가장 쉬움**: LLVM backend 사용 (`codegen/llvm.zig` 따라하기)
2. **중간**: C backend (기존 Zig C backend 포팅)
3. **최고**: self-hosted x86_64 / aarch64 (MIR 구조 그대로 따라하기)

**Phase 4: Linker + Build System**
- `link/` 디렉토리 거의 그대로 복사 가능
- `build.zig`도 Zig 자체로 구현됨

**Phase 5: Bootstrap & Self-host**
- 너의 컴파일러로 Zig 소스 자체를 컴파일할 수 있게 만들기
- Zig 팀도 이 과정에서 stage1(C++) → stage2(Zig)로 넘어옴

### 5. 현실적인 팁
- **완전 재구현**은 혼자 하면 1~2년 걸린다. (Zig 팀도 수년 걸림)
- 현실적으로는 **포크해서 수정**하거나 **subset 언어** (comptime 없이) 먼저 만드는 게 좋음.
