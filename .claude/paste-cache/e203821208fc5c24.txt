### 다음 단계 제안 (Phase 2 방향)

Type System Foundation의 다음 단계를 어떻게 진행하시겠습니까? 아래 중에서 선택하거나, 원하는 방향을 말씀해 주세요.

1. **Phase 2: 타입 검사 강화 (Hard Mode 전환 준비)**
   - Soft mode → **Hard mode**로 전환 (타입 에러 시 컴파일 실패)
   - 더 많은 타입 지원 확대: `f64`, `bool`, `string`, 배열(`[]T`), struct 필드 타입 검증 강화
   - 함수 시그니처 타입 검사 (`fn` 반환 타입, 매개변수 타입 매칭)
   - 타입 에러 메시지 개선 (구체적인 위치 + 친절한 설명)

2. **Phase 2: 타입 추론 (Type Inference) 기초 도입**
   - 일부 타입 어노테이션 생략 지원 (`let x = 5` → int로 추론)
   - Hindley-Milner 스타일 간단 추론 또는 로컬 추론 구현

3. **Phase 2: 기존 코드베이스 전체 타입 검사 적용**
   - `freelang-compiler` 내 모든 기존 테스트/예제에 타입 검사 강제 적용
   - 발생하는 타입 에러 일괄 수정 + 테스트 케이스 추가
   - TypeChecker 벤치마크 및 성능 측정

4. **문서화 및 검증 강화**
   - `TYPE_SYSTEM.md` 또는 `TypeChecker_API.md` 작성 (전체 타입 규칙 정리)
   - 단위 테스트 대폭 추가 (TypeChecker 전용 테스트 파일)
   - 메모리 인덱스 업데이트 + EVOLUTION_AUDIT.md 반영

5. **기타 방향**
   - struct 타입 완전 지원 (이미 struct 문법이 추가된 상태이니 필드 타입 검증 강화)
   - 에러 코드 체계화 (타입 관련 에러 코드 200번대 할당 등)
   - FreeLang Zero-Copy-DB와의 연계 (타입 시스템을 DB 스키마 검증에 활용?)
