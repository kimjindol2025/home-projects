## 1. 컴파일러 파이프라인 개요

Julia 코드가 CPU에서 실행되기까지 **8단계**를 거칩니다:

```
┌─────────────────────────────────────────────────────────────┐
│  [Julia 소스코드]                                            │
│  function f(x::Float64)                                      │
│      return sin(x) + 1.0                                     │
│  end                                                         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  1. AST 파싱 (Parsing)                                       │
│  → Meta.parse() 또는 quote로 확인                            │
│  → 구문 트리 (Expr) 생성                                     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  2. 로워링 (Lowering / Untyped IR)                           │
│  → @code_lowered로 확인                                      │
│  → goto 기반 제어흐름으로 변환                               │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  3. 타입 추론 (Type Inference / Typed SSA IR)                │
│  → @code_typed로 확인                                        │
│  → 모든 변수의 타입 확정, SSA 형식 변환                      │
│  → Phi 노드로 제어흐름 합류 처리                             │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  4. Julia SSA IR 최적화                                      │
│  → Julia 고유의 SSA IR에서 최적화 수행                       │
│  → 인라이닝, 상수 전파 등                                     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  5. LLVM IR 생성 (Codegen)                                   │
│  → @code_llvm으로 확인                                       │
│  → 플랫폼 독립적인 중간 표현                                   │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  6. LLVM 7단계 최적화                                        │
│  → Early Simplification → Loop Optimization → Vectorization  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  7. 네이티브 어셈블리 (Native Assembly)                        │
│  → @code_native으로 확인                                     │
│  → x86-64(또는 ARM) 기계어 생성                              │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  8. JIT 링킹 및 실행                                          │
│  → RuntimeDyld 또는 JITLink로 링킹                           │
│  → 메모리에 로드 → CPU 실행                                   │
└─────────────────────────────────────────────────────────────┘
```

**핵심 원리**: Julia는 **처음 호출 시** 해당 타입으로 컴파일합니다. 이후 동일 타입 호출 시 캐시된 기계어를 재사용합니다. [Julia Documentation](https://docs.julialang.org/en/v1/devdocs/jit/)

## 2. AST 파싱 단계 (Parsing)

소스 코드가 **추상 구문 트리(Abstract Syntax Tree, AST)** 로 변환됩니다.

### 2.1 기본 AST 파싱

```julia
# ============================================
# 📌 STEP 2: AST 파싱 — 소스코드 → 트리 구조
# ============================================

# 방법 1: 표현식 직접 파싱
expr = Meta.parse("x^2 + 2x + 1")
println(expr)
# 출력: :(x ^ 2 + 2x + 1)

# 방법 2: dump로 트리 구조 상세 확인
dump(expr)
# 출력:
# Expr
#   head: Symbol call
#   args: Array{Any}((3,))
#     1: Symbol +
#     2: Expr
#       head: Symbol call
#       args: Array{Any}((3,))
#         1: Symbol ^
#         2: Symbol x
#         3: Int64 2
#     ...

# 방법 3: quote 블록으로 함수 AST 보기
ast = quote
    function demo(x::Float64)
        y = sin(x)
        return y + 1.0
    end
end
dump(ast)

# 방법 4: 매크로 확장 전/후 AST 비교
println("매크로 확장 전:")
println(Meta.parse("@time sin(1.0)"))
# :(#= ... =# @time sin(1.0))

println("\n매크로 확장 후:")
println(macroexpand(Main, :(@time sin(1.0))))
# 실제로 @time이 무엇으로 확장되는지 볼 수 있음
```

### 2.2 AST 노드 종류

| 노드 종류 | 설명 | 예시 |
|-----------|------|------|
| `Expr` | 복합 표현식 | `:(x + y)` |
| `Symbol` | 변수/함수명 | `:x`, `:sin` |
| `Number` | 리터럴 숫자 | `5.0`, `2` |
| `LineNumberNode` | 소스 위치 정보 | `# line 3` |
| `QuoteNode` | 인용된 값 | `:(:x)` |

### 2.3 AST 직접 조작

```julia
# AST 직접 생성
my_expr = Expr(:call, :+, 1, 2)
println(my_expr)  # :(1 + 2)

# AST 수정
my_expr.args[2] = 10  # 두 번째 인수를 10으로 변경
println(my_expr)  # :(1 + 10)

# eval로 실행
result = eval(my_expr)
println(result)  # 11
```

## 3. 로워링 단계 (Lowering / Untyped IR)

AST를 **단순화된 중간 표현(IR)** 으로 변환합니다. 복잡한 문법 구조가 단순한 goto 문으로 바뀝니다.

### 3.1 로워드 IR 확인

```julia
using InteractiveUtils

# 기준 함수
function compiler_demo(x::Float64)
    y = sin(x)
    if x > 5.0
        y = y + cos(x)
    end
    return exp(2) + y
end

# 로워드 IR 확인
@code_lowered compiler_demo(3.14)
```

**예상 출력**:
```julia
CodeInfo(
1 ─      y = Main.sin(x)
│   %2 = x > 5.0
└──      goto #3 if not %2
2 ─ %4 = Main.cos(x)
│        y = y + %4
3 ─ %6 = Main.exp(2)
│   %7 = %6 + y
└──      return %7
)
```

### 3.2 로워링의 핵심 변환

```julia
# ------------------------------------
# 비교: 루프가 있는 함수는 어떻게 로워링되나?
# ------------------------------------
function loop_demo(n::Int)
    s = 0
    for i in 1:n
        s += i
    end
    return s
end

@code_lowered loop_demo(10)
# for 루프 → goto 기반 제어흐름으로 변환되는 것 확인

# ------------------------------------
# 비교: 타입 없는 함수 vs 타입 있는 함수
# ------------------------------------
f_untyped(x) = x * 2
f_typed(x::Int) = x * 2

@code_lowered f_untyped(5)
@code_lowered f_typed(5)
# 거의 동일! 타입 추론은 다음 단계에서 발생
```

**로워링의 핵심 변환**:
- `if/else` → `goto #블록번호 if not 조건`
- `for 루프` → `goto` 기반 점프
- 복합 표현식 → `%1, %2 ...` 임시 변수로 분리
- 매크로 → 실제 코드로 완전 확장

## 4. 타입 추론 단계 (Type Inference / Typed SSA IR)

Julia의 핵심! 컴파일러가 **모든 변수의 타입**을 추론하여 최적화된 IR을 생성합니다.

### 4.1 타입 추론된 IR 확인

```julia
# 타입 추론된 IR 확인
@code_typed compiler_demo(3.14)
```

**예상 출력**:
```julia
CodeInfo(
1 ─ %1 = Base.Math.sin(x)::Float64        ← 타입 확정!
│   %2 = Base.lt_float(x, 5.0)::Bool      ← Bool로 추론
└──      goto #3 if not %2
2 ─ %4 = Base.Math.cos(x)::Float64
│   %5 = Base.add_float(%1, %4)::Float64  ← add_float 특화됨
3 ─ %6 = φ (#2 => %5, #1 => %1)::Float64 ← Phi 노드!
│   %7 = Base.add_float(7.38905609893065, %6)::Float64
└──      return %7
) => Float64                               ← 반환 타입도 확정
```

### 4.2 타입 안정성 분석

**⚠️ 타입 불안정 함수 — 성능 저하의 주범**:

```julia
# ❌ 타입 불안정 — 성능 저하
function type_unstable(x)
    if x > 0
        return x        # Int 또는 Float 반환
    else
        return "음수"   # String 반환 ← 타입 충돌!
    end
end

@code_warntype type_unstable(5)
# 반환 타입이 Union{Int64, String} 또는 Any → 성능 저하
```

**✅ 타입 안정 버전으로 수정**:

```julia
function type_stable(x::Float64)
    if x > 0.0
        return x
    else
        return 0.0   # 동일한 타입 반환
    end
end

@code_warntype type_stable(5.0)
# 반환 타입이 Float64로 깔끔하게 추론됨 — 빨간색 경고 없음
```

### 4.3 타입 추론 규칙

| 상황 | 타입 결과 | 성능 |
|------|-----------|------|
| 구체적 타입 인수 | `Float64`, `Int64` | ✅ 빠름 |
| 전역 변수 사용 | `Any` | ❌ 느림 |
| Union 반환 | `Union{A, B}` | ⚠️ 보통 |
| 타입 매개변수 | `T<:Number` | ✅ 빠름 |

### 4.4 SSA 중간 표현 (Static Single Assignment IR)

Julia만의 고유한 **SSA 형식 IR**을 심층 분석합니다.

```julia
# SSA IR의 핵심: 각 변수는 단 한 번만 할당됨
# 제어흐름 합류점에서는 Phi 노드 사용

function ssa_demo(x::Int)
    if x > 10
        y = x * 2    # 경로 A
    else
        y = x + 1    # 경로 B
    end
    return y         # 어느 경로에서 왔는지 Phi가 결정!
end

@code_typed ssa_demo(5)
# 출력에서 φ 노드 확인:
# %3 = φ (#2 => %1, #1 => %2)::Int64
#        ↑ 블록2에서 오면 %1, 블록1에서 오면 %2
```

**Phi 노드 작동 원리**:
```julia
function phi_example(cond::Bool, a::Float64, b::Float64)
    x = cond ? a * 2.0 : b + 1.0  # 삼항 연산자
    return x + 100.0
end

@code_typed phi_example(true, 3.14, 2.71)
# %1 = Base.mul_float(a, 2.0)::Float64   ← true 경로
# %2 = Base.add_float(b, 1.0)::Float64   ← false 경로
# %3 = φ (#2 => %1, #3 => %2)::Float64  ← Phi 합류!
# %4 = Base.add_float(%3, 100.0)::Float64
# return %4
```

## 5. LLVM IR 생성 (Codegen)

Julia SSA IR이 **LLVM 중간 표현**으로 변환됩니다.

### 5.1 LLVM IR 확인

```julia
# LLVM IR 출력
@code_llvm compiler_demo(3.14)
```

**예상 출력**:
```llvm
define double @julia_compiler_demo_XXXX(double %0) {
top:
  %1 = call double @julia_sin_XXXX(double %0)   ; sin(x)
  %2 = fcmp ogt double %0, 5.000000e+00          ; x > 5.0
  br i1 %2, label %L4, label %L6                 ; goto if not
L4:
  %3 = call double @julia_cos_XXXX(double %0)   ; cos(x)
  %4 = fadd double %1, %3                        ; y + cos(x)
L6:
  %5 = phi double [ %4, %L4 ], [ %1, %top ]     ; Phi 노드
  %6 = fadd double 7.389056e+00, %5             ; exp(2)+y (상수화!)
  ret double %6
}
```

### 5.2 LLVM 최적화 확인

```julia
# ------------------------------------
# ✨ 최적화 전후 비교: 상수 폴딩
# ------------------------------------
f_const() = 2^10 + 1000 - 500
@code_llvm f_const()
# → LLVM이 컴파일 시간에 계산: ret i64 1524
# 실행 시 연산 0번!

# ------------------------------------
# ✨ 최적화: 인라이닝(Inlining) 확인
# ------------------------------------
@inline square(x::Float64) = x * x

function use_square(x::Float64)
    return square(x) + 1.0
end

@code_llvm use_square(3.0)
# square() 호출이 사라지고 인라이닝됨:
# %2 = fmul double %0, %0   ← 직접 곱셈!
# %3 = fadd double %2, 1.0
```

## 6. 네이티브 어셈블리 (Native Assembly)

최종 단계: 실제 CPU가 실행하는 **x86-64 어셈블리 코드**를 확인합니다.

### 6.1 어셈블리 확인

```julia
# 어셈블리 출력
@code_native compiler_demo(3.14)
```

**예상 출력** (x86-64):
```asm
.text
  pushq   %rbp
  movq    %rsp, %rbp
  ...
  callq   julia_sin_XXXX     ; sin 함수 호출
  ucomisd %xmm0, %xmm1       ; 부동소수점 비교
  jbe     .L1                 ; 조건 점프
  callq   julia_cos_XXXX     ; cos 함수 호출
  addsd   %xmm1, %xmm0       ; 부동소수점 덧셈
.L1:
  addsd   .rodata(%rip), %xmm0  ; exp(2) + y
  popq    %rbp
  retq                        ; 반환
```

### 6.2 극한 최적화 예시

```julia
# ------------------------------------
# 🔥 극한 최적화: 정수 덧셈은 단 1 명령어!
# ------------------------------------
add_ints(x::Int64, y::Int64) = x + y

@code_native add_ints(1, 2)
# .text
#   leaq  (%rdi,%rsi), %rax   ← 덧셈 1 명령어!
#   retq
```

## 7. JIT 캐싱 및 다중 디스패치

### 7.1 다중 디스패치 (Multiple Dispatch)

**같은 함수가 타입마다 다른 기계어**를 생성하는 Julia 핵심 원리.

```julia
# 하나의 함수 — 타입별로 다른 기계어 생성
function my_mul(x, y)
    return x * y
end

# Int × Int
@code_native my_mul(2, 3)
# imulq 명령어 사용 (정수 곱셈)

# Float64 × Float64
@code_native my_mul(2.0, 3.0)
# mulsd 명령어 사용 (부동소수점 곱셈)

# 생성된 메서드 목록 확인
println(methods(my_mul))
```

### 7.2 JIT 캐싱 확인

```julia
using BenchmarkTools

heavy_fn(x::Float64) = sum(sin(x + i) for i in 1:1000)

# 첫 호출: 컴파일 시간 포함
@time heavy_fn(1.0)    # 느림 (컴파일 포함)
@time heavy_fn(1.0)    # 빠름 (캐시 재사용)

# 정확한 벤치마크 (워밍업 포함)
@benchmark heavy_fn(1.0)
```

## 8. 성능 최적화 패턴

### 8.1 @inbounds — 경계 검사 제거

```julia
using BenchmarkTools

# ------------------------------------
# @inbounds: 배열 경계 검사 제거
# ------------------------------------
function sum_bounds(v::Vector{Float64})
    s = 0.0
    for i in 1:length(v)
        s += v[i]       # 매번 경계 검사 실행
    end
    return s
end

function sum_inbounds(v::Vector{Float64})
    s = 0.0
    @inbounds for i in 1:length(v)
        s += v[i]       # 경계 검사 SKIP
    end
    return s
end

v = rand(100000)
@benchmark sum_bounds($v)   # 느림
@benchmark sum_inbounds($v) # 빠름 (약 20-30% 향상)

# @code_llvm으로 차이 확인
@code_llvm sum_bounds(v)     # bounds check 코드 있음
@code_llvm sum_inbounds(v)   # bounds check 코드 없음!
```

### 8.2 @simd — SIMD 벡터화 강제

```julia
function sum_scalar(v::Vector{Float64})
    s = 0.0
    for x in v
        s += x
    end
    return s
end

function sum_simd(v::Vector{Float64})
    s = 0.0
    @simd for x in v
        s += x
    end
    return s
end

@benchmark sum_scalar($v)
@benchmark sum_simd($v)     # SIMD로 4-8배 빠를 수 있음
```

### 8.3 @inline — 함수 인라이닝 강제

```julia
@inline fast_square(x::Float64) = x * x
@noinline slow_square(x::Float64) = x * x  # 인라이닝 금지

function compute_fast(x::Float64)
    return fast_square(x) + fast_square(x + 1.0)
end

function compute_slow(x::Float64)
    return slow_square(x) + slow_square(x + 1.0)
end

@code_llvm compute_fast(2.0)  # 함수 호출 없음, 직접 fmul
@code_llvm compute_slow(2.0)  # callq 명령어 있음

@benchmark compute_fast(2.0)
@benchmark compute_slow(2.0)  # 함수 호출 오버헤드 있음
```

### 8.4 @generated — 컴파일 시간 코드 생성

```julia
@generated function typed_zeros(::Type{T}, n::Int) where T
    # 이 코드는 컴파일 시간에 실행됨!
    return :(zeros($T, n))
end

@time typed_zeros(Float64, 1000000)
@time typed_zeros(Int32, 1000000)
# 각 타입별로 최적화된 코드 생성
```

## 9. BenchmarkTools 활용

### 9.2 벤치마크 비교

```julia
# 타입 안정 vs 불안정 비교
v = rand(10000)

# ❌ 타입 불안정
function unstable(v)
    s = 0          # Int로 시작
    for x in v
        s += x     # Float이 들어오면 타입 변경!
    end
    return s
end

# ✅ 타입 안정
function stable(v::Vector{Float64})
    s = 0.0        # Float64로 명시
    for x in v
        s += x
    end
    return s
end

@benchmark unstable($v)   # 느림
@benchmark stable($v)     # 빠름 (수십 배 차이!)
```

## 10. 실전 프로젝트: 고성능 수치 계산 라이브러리

### 10.1 완전한 고성능 벡터 거리 계산기

```julia
using BenchmarkTools
using InteractiveUtils

# ============================================
# 고성능 벡터 거리 계산기 (컴파일러 최적화 완전 적용)
# ============================================

# -----------------------------------------------
# 버전 1: 순진한 구현 (최적화 없음)
# -----------------------------------------------
function euclidean_naive(a::Vector{Float64}, b::Vector{Float64})
    s = 0
    for i in 1:length(a)
        diff = a[i] - b[i]
        s = s + diff * diff
    end
    return sqrt(s)
end

# -----------------------------------------------
# 버전 2: 타입 안정 + 컴파일러 힌트 최적화
# -----------------------------------------------
function euclidean_optimized(a::Vector{Float64}, b::Vector{Float64})
    s = 0.0            # Float64로 타입 고정
    @inbounds @simd for i in eachindex(a)
        diff = a[i] - b[i]
        s += diff * diff
    end
    return sqrt(s)
end

# -----------------------------------------------
# 버전 3: 타입 파라미터로 일반화
# -----------------------------------------------
function euclidean_generic(a::AbstractVector{T}, b::AbstractVector{T}) where {T<:AbstractFloat}
    s = zero(T)        # T 타입의 0
    @inbounds @simd for i in eachindex(a)
        diff = a[i] - b[i]
        s += diff * diff
    end
    return sqrt(s)
end

# -----------------------------------------------
# 컴파일러 파이프라인 전체 분석
# -----------------------------------------------
a = rand(10000)
b = rand(10000)

println("📊 컴파일러 분석 리포트")
println("="^60)

# 1. 타입 추론 상태 확인
println("\n[1] 타입 추론 (Typed IR):")
@code_typed euclidean_optimized(a, b)

# 2. LLVM 최적화 확인
println("\n[2] LLVM IR (최적화됨):")
@code_llvm euclidean_optimized(a, b)

# 3. 네이티브 어셈블리 확인
println("\n[3] Native Assembly:")
@code_native euclidean_optimized(a, b)

# -----------------------------------------------
# 성능 비교 벤치마크
# -----------------------------------------------
println("\n[4] 성능 벤치마크:")
println("Naive 버전:")
@benchmark euclidean_naive($a, $b)

println("\nOptimized 버전:")
@benchmark euclidean_optimized($a, $b)

println("\nGeneric 버전:")
@benchmark euclidean_generic($a, $b)

# -----------------------------------------------
# 메서드 디스패치 확인
# -----------------------------------------------
println("\n[5] 디스패치 경로:")
@which euclidean_generic(a, b)
println(methods(euclidean_generic))

# -----------------------------------------------
# 타입별 특화 확인 (Float32 vs Float64)
# -----------------------------------------------
a32 = rand(Float32, 10000)
b32 = rand(Float32, 10000)

println("\n[6] Float32 특화 버전:")
@code_native euclidean_generic(a32, b32)
# Float64와 다른 어셈블리 생성 확인 (mulss vs mulsd)

println("\n✅ Float64 vs Float32 성능 비교:")
@benchmark euclidean_generic($a, $b)     # Float64
@benchmark euclidean_generic($a32, $b32)  # Float32 (더 빠를 수 있음)
```

## 📊 전체 컴파일러 파이프라인 요약

```
소스코드          →  Meta.parse()        →  AST (Expr 트리)
AST               →  Lowering            →  @code_lowered
Untyped IR        →  Type Inference      →  @code_typed
Typed IR          →  Codegen             →  LLVM IR (@code_llvm)
LLVM IR           →  7단계 최적화         →  최적화된 LLVM IR
최적화 LLVM IR    →  어셈블리 생성        →  @code_native
Native code       →  JIT 링킹            →  CPU 실행
```

| 단계 | 명령어 | 보여주는 것 |
|------|--------|------------|
| AST 파싱 | `Meta.parse()` + `dump()` | 구문 트리 구조 |
| 로워링 | `@code_lowered` | goto 기반 단순화 IR |
| 타입 추론 | `@code_typed` | 타입 확정 SSA IR |
| LLVM IR | `@code_llvm` | 플랫폼 독립 IR |
| 어셈블리 | `@code_native` | 실제 CPU 명령어 |
