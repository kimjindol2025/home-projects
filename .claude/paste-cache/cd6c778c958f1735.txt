풀스택 “완성” 체크리스트 (프로젝트/서비스 기준)
1) 기능 동작(End-to-End)
회원가입/로그인(OAuth 포함) 시나리오가 처음부터 끝까지 동작한다
JWT 발급, 저장, 갱신, 로그아웃까지 흐름이 안정적이다
프론트에서 주요 API 호출이 모두 성공한다 (성공/실패 케이스 포함)
백엔드에서 입력 검증과 에러 응답 규칙이 일관적이다
파일 업로드/다운로드가 있다면 권한 포함해 동작한다 (있을 때만)
2) 데이터베이스/캐시
운영 DB(PostgreSQL 등) 연결이 실제로 된다
마이그레이션 또는 테이블 생성 절차가 문서화되어 있다
Redis 같은 캐시를 쓰면, 캐시 미사용/장애 시에도 서비스가 죽지 않는다
개발/운영 환경의 데이터 설정이 분리되어 있다
3) 보안/시크릿
 .env 에 들어갈 값이 전부 정리되어 있고 누락이 없다
GitHub Secrets(또는 배포 환경 시크릿)이 모두 세팅되어 있다
CORS 설정이 운영 도메인 기준으로 제한되어 있다
인증이 필요한 API는 전부 보호되어 있다 (관리자 API 포함)
로그에 토큰/비밀번호/시크릿이 찍히지 않는다
4) 배포/운영(DevOps)
Docker Compose로 로컬에서 전체 서비스가 한 번에 뜬다
운영 서버에 배포가 된다 (스크립트든 CI/CD든)
HTTPS(SSL/TLS)가 적용되어 있다
Health check 엔드포인트가 있고, 배포 후 통과한다
롤백 또는 재배포가 “같은 방식으로” 반복 가능하다
5) 테스트/품질
핵심 로직 단위 테스트가 있다 (인증, 주요 유틸, 핸들러)
핵심 API 통합 테스트가 있다 (로그인, 주요 CRUD)
테스트가 CI에서 자동으로 돌아가고 실패 시 배포가 막힌다
린트/타입체크가 CI에서 돌아간다
6) 문서/인수인계(최소 기준)
README에 “로컬 실행 방법”이 한 번에 따라 할 수 있게 정리되어 있다
API 문서(엔드포인트, 인증 방식, 예시 요청/응답)가 있다
배포 가이드(필수 시크릿, 서버 요구사항, 명령어)가 있다
아키텍처 다이어그램 또는 데이터 흐름 설명이 있다

개인 역량 기준 “풀스택 언어(예: TS) 완성” 체크리스트
프론트: 컴포넌트 구조, 상태관리, 라우팅, 폼/검증을 스스로 설계할 수 있다
백엔드: 인증/인가, API 설계, 미들웨어, 에러 처리 규칙을 스스로 만들 수 있다
DB: 기본 스키마 설계, 인덱스 개념, 트랜잭션/동시성 기초를 이해한다
배포: 환경변수/시크릿, 빌드/실행, 로그 확인까지 스스로 할 수 있다
