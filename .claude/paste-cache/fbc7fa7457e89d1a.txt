이 저장소(freelang-self-hosting-proof)는 **현재 시점(2026년 3월 기준)** 에서 보면

**실제로는 완전한 의미의 self-hosting(자체 호스팅) 증명은 아직 이루어지지 않았다**  
고 보는 것이 기술적으로 정확합니다.

주요 이유와 현재 상황을 단계별로 정리해 드릴게요.

### 1. 무엇을 보여주고 싶은가? (저장소의 주장)

- simple-http.free 라는 아주 간단한 HTTP 서버 코드(println 위주, 15개 함수)를  
  JavaScript로 작성된 컴파일러(full-e2e-compiler.js)로 컴파일 → ELF 바이너리 생성
- 같은 소스를 **세 번 반복 컴파일** 했을 때 나오는 바이너리가 **모두 동일**하다 (MD5 동일)
- → "결정적(deterministic) 컴파일"임을 보여줌
- → "그래서 v2 == v3가 보장된다" → "fixed-point에 도달했다" → "self-hosting 증명 완료"

### 2. 결정적인 문제점 (가장 중요한 부분)

현재 보여주는 3단계 부트스트랩은 **진짜 부트스트랩이 아니다**

```text
v1 = JS컴파일러 → simple-http.free
v2 = JS컴파일러 → simple-http.free     ← v1을 사용한 게 아님
v3 = JS컴파일러 → simple-http.free     ← v2를 사용한 게 아님
```

→ **v1, v2, v3 모두 같은 JS 컴파일러가 만들어낸 결과물**일 뿐이다.

진짜 self-hosting 부트스트랩은 이렇게 진행되어야 한다:

```text
v1 = JS컴파일러 → compiler-in-freelang.free
v2 = v1 바이너리 실행 → compiler-in-freelang.free
v3 = v2 바이너리 실행 → compiler-in-freelang.free
→ v2와 v3가 byte-for-byte 동일해야 증명 성립
```

지금 저장소는 **2번과 3번 단계를 실제로 수행하지 못했다**.

### 3. 왜 v2, v3를 실제로 못 만들었나?

문서에 본인들이 솔직하게 적어놓은 주요 blocker들:

- JavaScript 단계의 파서가 **struct 문법을 지원하지 않음**
- freelang-compiler-complete.fl (자기 자신 컴파일러 소스)에는 struct가 많이 들어감
- → JS 컴파일러로는 **자기 자신을 컴파일할 수 없다**
- v1 바이너리는 x86-64로 생성되었는데 실행 환경은 **ARM64** (아마도 애플 M 시리즈 또는 안드로이드 태블릿?)
- → "Illegal instruction" 에러
- FreeLang 런타임이 제대로 설치되지 않음

→ **결국 v1 바이너리를 실제로 실행해서 자기 자신을 컴파일하는 단계는 전혀 구현되지 않았다.**

### 4. 그럼 이 저장소가 의미 있는 부분은?

있습니다. 아래는 긍정적으로 평가할 수 있는 점들입니다.

- 아주 작은 서브셋 언어로 작성된 프로그램(simple-http.free)을  
  실제로 ELF 바이너리까지 만들어냈다 → 컴파일러 앞단(lexer ~ codegen ~ ELF)이 어느 정도 동작함을 보여줌
- 컴파일 결과가 **결정적**이라는 점은 잘 증명함 (같은 소스 → 항상 같은 바이너리)
- 문서화가 매우 철저하고, 재현 스크립트까지 제공함
- "기록이 증명이다" 라는 철학 아래 최대한 투명하게 공개하려는 태도는 높이 평가할 만함

### 5. 요약 — 현실적 판단

현재 단계          | 상태          | self-hosting 증명으로 인정될 수 있나?
------------------------|---------------|------------------------------------
JS → simple-http.free 컴파일 | 성공          | 부분 성공 (아주 작은 서브셋)
결정적 컴파일 증명       | 성공          | 의미 있음
v1 바이너리가 존재       | 성공          | 의미 있음
v1 실행 → 자기 자신 컴파일 | **실패**      | **핵심이 안 됨**
v2 == v3 실제 생성 & 비교 | **실패**      | **핵심이 안 됨**
struct 지원 자기 컴파일러 컴파일 | **실패**      | 아직 멀었다

**결론 (2026년 3월 기준)**  
→ "FreeLang이 self-hosting 가능한 언어임을 증명했다"는 주장은 **아직 과장**입니다.  
→ "self-hosting을 향한 첫걸음으로 결정적 컴파일과 아주 작은 프로그램의 ELF 생성에 성공했다"는 표현이 더 정확합니다.
