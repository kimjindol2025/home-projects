## 📋 전용 명령 (Custom Alias)

### /check-logic
**목적**: 현재 코드의 타입 안전성 및 의존성 검사

**실행**:
```
현재 작성된 모든 함수의 입출력 타입을 검사하세요.
의존성 선언이 없는 부분을 찾으세요.
외부 라이브러리가 호출되는지 확인하세요.

| 함수명 | 입력(타입) | 출력(타입) | 의존성 | 외부호출 |
|--------|----------|----------|--------|---------|
```

---

### /save-proof
**목적**: 작업 내용 → GOGS 커밋 메시지 자동 정리

**실행**:
```
지금까지의 작업 내용을 요약해주세요.

GOGS 커밋 메시지 규격:
[타입] 제목 (50자 이내)

상세:
- 변경사항 (불릿)
- 테스트 결과
- 증빙 데이터

PLAN.md를 업데이트하세요.
마지막으로 출력:
"저장 필수, 기록이 증명이다 gogs"
```

---

### /verify-vanilla
**목적**: 외부 라이브러리 의존성 전수 조사

**실행**:
```
외부 라이브러리 호출을 전수 조사하세요.

| 라이브러리 | 호출 위치 | 순수코드 대체 | 대체안 |
|----------|---------|-----------|------|

'외부 의존성 제로' 달성 로드맵을 제시하세요.
```

---

### /red-team [aspect]
**목적**: 설계 약점 찾기

**범주**: 성능 | 메모리누수 | 확장성 | 보안

**실행**:
```
가장 먼저 터질 취약점을 분석하세요.

1. 취약점: ~
   원인: ~
   재현 조건: ~
   영향도: 1~5
2. ...

각 취약점마다 해결 방안을 제시하세요.
```

---

### /refactor-first [기능명]
**목적**: 기능 추가 전, 기존 구조 성능 10% 개선 검토

**실행**:
```
[기능명]을 구현하기 전에,
기존 FreeLang 엔진 성능을 10% 향상시키면서
이 기능을 넣을 수 있는 구조적 대안을 제시해주세요.

분석 기준:
- 메모리 레이아웃 (SoA vs AoS)
- 캐시 지역성 (L1/L2/L3)
- 호출 경로 (함수 호출 오버헤드)
- 병렬화 가능성

결과:
현재: [메트릭]
개선안: [메트릭]
성능 향상: X%
```

## 🎯 Shadow Architect (자동 검증)

매 코드 작성 완료 시 자동 실행:

### 1단계: Red Team Analysis
- 가장 큰 성능 병목은?
- 메모리 누수 가능성은?
- 확장할 때 깨질 부분은?

### 2단계: Refactor-First Check
- 기존 코드 10% 성능 개선 부분?
- 구조 변경으로 신규 기능을 더 우아하게 통합?
- 함수 호출 체인 단축 가능?

### 3단계: Vanilla Check
- 외부 라이브러리 호출 있는가?
- 순수 코드로 대체 가능한가?

### 4단계: Proof Record
- GOGS 커밋 형식 요약
- 벤치마크/타입 검사 증빙
- HISTORY.gogs에 누적
