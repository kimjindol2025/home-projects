# FreeLang Brand Voice Guide

FreeLang 마케팅 팀의 모든 콘텐츠는 다음 브랜드 보이스를 준수합니다.

## 핵심 가치

| 가치 | 설명 |
|------|------|
| **실용성** | 이론만 아닌 실제 사용할 수 있는 코드와 예시 제공 |
| **포용성** | 초보자부터 전문가까지 모두 이해할 수 있게 설명 |
| **투명성** | 장점도 단점도 공정하게 소개 |
| **신뢰성** | 검증된 정보만 제시 (근거 필수) |
| **친근함** | 딱딱한 기술 문서가 아닌 대화체 톤 |

## 톤앤매너

### 하지 말 것
❌ "최고다", "최강이다", "완벽하다" (과장)
❌ "다른 언어는 못한다" (비난)
❌ "저희 회사" (개인성 보다는 팀)
❌ "당신은 이것을 모를 것 같은데..." (상대방 무시)
❌ 기술 용어만 나열 (초보자 배려)

### 하는 것
✅ "우리의 경험상...", "테스트 결과..." (근거 제시)
✅ "~할 수 있습니다", "좋은 선택입니다" (긍정)
✅ "다른 접근: ..., 우리의 접근: ..." (비교)
✅ "초보자라면? 전문가라면?" (수준별 설명)
✅ "한계: ..., 개선 방안: ..." (균형잡힌 설명)

## 언어 규칙

### 한국어
- **기본 문체**: 존댓글 (개발자 친근성)
- **예시**: "이렇게 하면 돼요", "궁금하신가요?"
- **기술용어**: 한글 설명 + 영문 병기
  ```
  예: "가비지 컬렉션(Garbage Collection)을..."
  ```
- **문단 길이**: 3-5문장 (너무 길지 않게)
- **문체 변화**: 반복되지 않게 문장 구조 다양화

### 영문
- **톤**: Professional but friendly
- **시제**: 현재형 사용 (문서는 예외)
- **코드**: 영문 변수명, 한글 주석 (한국 독자 배려)
- **예시**: "Here's how to do it" (How-to 스타일)

## 콘텐츠별 가이드

### 블로그 포스트
```
구조:
1. 제목: SEO 최적화 + 호기심 자극
   예: "FreeLang의 메모리 관리가 C와 다른 이유"

2. 요약 (150자)
   핵심 3줄 + 읽으면 얻을 수 있는 것

3. 본론
   배경 → 문제 → 해결책 → 코드 예시 → 결론

4. 마무리
   다음 읽을 거리, 문의, 피드백

톤: 교사가 학생을 가르치듯 (설득이 아닌 설명)
```

### 소셜미디어
```
Twitter/X:
- 한 줄 요약 + 주요 정보 3개 + 링크
- 톤: 경쾌하고 인포메이션 풍부

LinkedIn:
- 전문 인사이트 강조
- "왜 이것이 중요한가?" 설명
- 톤: 전문가적이지만 개인적

Reddit/GeekNews:
- 질문에 상세 답변 (200자 이상)
- "우리도 같은 문제..."로 공감
- 톤: 커뮤니티 멤버처럼 (홍보 자제)
```

## 금지 표현

| 표현 | 대신 |
|------|------|
| "최고", "최강", "최상" | "효율적", "좋은 성과", "우수한" |
| "저희가 유일하게..." | "우리의 접근방식..." |
| "이건 쉽다" | "단순한 구조로..." |
| "당신도 알겠죠?" | "이렇게 생각해보세요" |
| "완벽한" | "잘 설계된" |
| "이 언어만..." | "우리는 이렇게..." |

## 체크리스트

발행 전 확인:
- [ ] 너무 기술적이지 않은가? (초보자 이해 가능?)
- [ ] 근거가 있는가? (근거 링크 포함?)
- [ ] 과장이 없는가? ("최고" 같은 표현 없나?)
- [ ] 균형잡혀 있는가? (장단점 모두?)
- [ ] 친근한가? (딱딱하지 않은가?)
- [ ] 명확한가? (이 글로 무엇을 배우나?)

---

**핵심**: 프로그래머는 "팔기 위한" 마케팅보다
"배울 수 있는" 콘텐츠를 더 신뢰합니다.
