## 🔄 Data Flow Architecture

```
Input: Git Tree Object (from tree.fl)
  │
  ├─ mode: "100644"
  ├─ type: "blob" or "tree"
  ├─ hash: "a1b2c3d4..."
  └─ name: "filename.txt"

  ▼

[PARSER]
  parseTreeEntryLine() ──> Parse "mode type hash\tname" format
  parseTreeData() ──────> Process multi-line tree data

  ▼

[TRANSFORMER]
  buildWebTreeNode() ───> Create web-compatible node
  convertTreeToJSON() ──> Recursive JSON transformation

  ▼

[API]
  createTreeAPIResponse() ──> Wrap in API response format
  serializeWebTree() ───────> Convert to JSON string

  ▼

Output: Browser-Ready JSON
  {
    "name": "root",
    "type": "tree",
    "hash": "abc123def456",
    "children": [
      {
        "name": "file.txt",
        "type": "blob",
        "hash": "hash1",
        "shortHash": "hash1xxx",
        "icon": "📄",
        "path": "/file.txt"
      },
      {
        "name": "src",
        "type": "tree",
        "icon": "📁",
        "children": [],
        "loadable": true
      }
    ]
  }
```

## 🔧 Core Functions

### 1. buildWebTreeNode()
```
Purpose: Create single web-compatible node
Input: name, type, hash, size
Output: Map with web properties

Properties Generated:
  ✓ name, type, hash
  ✓ shortHash (first 8 chars)
  ✓ icon (📄 for blob, 📁 for tree)
  ✓ path (constructed from parent)
  ✓ children[] (empty, for trees)
  ✓ expanded (false, for lazy loading)
```

### 2. parseTreeEntryLine()
```
Purpose: Parse single tree entry line
Format: "100644 blob a1b2c3d4\tfile.txt"

Processing:
  1. Split on tab character
  2. Parse left side (mode type hash)
  3. Extract name from right side
  4. Return structured map
```

### 3. parseTreeData()
```
Purpose: Parse complete tree data string
Input: Multi-line tree data ("mode type hash\tname\n...")
Output: Array of parsed entries

Algorithm:
  1. Iterate through data character by character
  2. Accumulate characters until newline
  3. Call parseTreeEntryLine() for each line
  4. Return array of entries
```

### 4. convertTreeToJSON()
```
Purpose: Recursively convert tree to JSON format
Process:
  1. Read tree object entries
  2. For each entry:
     a. Create web node via buildWebTreeNode()
     b. If tree: add loadable flag + empty children
     c. If blob: just add to children
  3. Return hierarchical structure
  4. Include metadata (timestamp, version)
```

### 5. createTreeAPIResponse()
```
Purpose: Wrap JSON tree in API response
Structure:
  {
    "success": true,
    "data": <web tree>,
    "meta": {
      "endpoint": "/api/tree",
      "method": "GET",
      "timestamp": 1710610800,
      "version": "1.0"
    }
  }
```

## 🚀 Lazy-Loading Strategy

The renderer prepares for frontend optimization:

```javascript
// Frontend JavaScript (pseudo-code)
when user clicks on folder {
  if (node.loadable === true) {
    fetch('/api/tree?hash=' + node.hash)
      .then(response => response.json())
      .then(data => {
        node.children = data.children
        node.expanded = true
      })
  }
}
```

**Benefits**:
- ✅ Large trees don't overwhelm initial load
- ✅ Only fetch subtrees when needed
- ✅ Progressive disclosure (UX best practice)
- ✅ Scales to 155+ repositories

## 🔄 Data Flow Architecture

```
Input: Delta Instructions (from delta.fl)
  │
  ├─ instruction: "COPY"     (unchanged content)
  ├─ instruction: "ADD"      (new content)
  └─ instruction: "SKIP"     (deleted content)

  ▼

[DELTA → BLOCK CONVERTER]
  convertDeltaInstructionsToBlocks()
  ├─ COPY → { type: "unchanged", baseLineNum: N, newLineNum: N }
  ├─ ADD  → { type: "added",     baseLineNum: -1, newLineNum: N }
  └─ SKIP → { type: "removed",   baseLineNum: N,  newLineNum: -1 }

  ▼

[DIFF BLOCK CLASSIFIER]
  getClassNameForType()
  ├─ "added"      → "diff-added"      (CSS class)
  ├─ "removed"    → "diff-removed"    (CSS class)
  ├─ "modified"   → "diff-modified"   (CSS class)
  └─ "unchanged"  → "diff-unchanged"  (CSS class)

  ▼

[HTML/JSON RENDERER]
  renderDiffToHtml() or convertDiffBlocksToJson()
  ├─ HTML: <table> with styled rows
  └─ JSON: Block array + statistics

  ▼

[API RESPONSE WRAPPER]
  createDiffHtmlResponse() or createDiffJsonResponse()
  {
    "success": true,
    "format": "html" or "json",
    "data": { /* rendered diff */ },
    "meta": { "endpoint": "/api/diff", ... }
  }

  ▼

Output: Browser-Ready Visual Diff
  Red (#ffebee):    Removed lines (-) 🟥
  Green (#e8f5e9):  Added lines (+)   🟩
  Orange (#fff3e0): Modified lines (~) 🟧
  White (#ffffff):  Unchanged lines    ⚪
```

## 🔧 Core Functions

### 1. createDiffBlock()
```
Purpose: Create single diff line block
Input: lineType, lineNumber, content, baseLineNum, newLineNum
Output: Map with diff properties

Properties Generated:
  ✓ type (added/removed/modified/unchanged)
  ✓ lineNumber (sequence index)
  ✓ baseLineNum (original file line, or -1)
  ✓ newLineNum (new file line, or -1)
  ✓ content (line text)
  ✓ className (CSS class)
  ✓ html (rendered HTML, set later)
```

### 2. convertDeltaInstructionsToBlocks()
```
Purpose: Transform delta instructions → diff blocks
Process:
  1. Iterate through delta instruction array
  2. For each instruction:
     - COPY: Extract content, create "unchanged" block
     - ADD: Create "added" block (baseLineNum = -1)
     - SKIP: Extract skipped content, create "removed" block
  3. Build line numbering sequentially
  4. Return array of classified blocks
```

### 3. renderDiffBlockToHtml()
```
Purpose: Convert single block to HTML table row
HTML Structure:
  <tr class="[className]">
    <td class="line-num base">[baseLineNum or -]</td>
    <td class="line-num new">[newLineNum or -]</td>
    <td class="marker">[+/- marker]</td>
    <td class="content"><code>[escaped content]</code></td>
  </tr>

Markers:
  + : Added line (green)
  - : Removed line (red)
  ~ : Modified line (orange)
    : Unchanged line (space)
```

### 4. renderDiffToHtml()
```
Purpose: Full diff → HTML table
Structure:
  <table class="diff-table">
    <thead>
      <tr class="diff-header">
        <th>Base</th>
        <th>New</th>
        <th></th>
        <th>Changes</th>
      </tr>
    </thead>
    <tbody>
      [renderDiffBlockToHtml() for each block]
    </tbody>
  </table>
```

### 5. convertDiffBlocksToJson()
```
Purpose: Alternative JSON format for API
Output:
  {
    "format": "json",
    "totalBlocks": N,
    "blocks": [ /* array of blocks */ ],
    "stats": {
      "added": count,
      "removed": count,
      "modified": count,
      "unchanged": count
    }
  }
```

### 6. createDiffSummary()
```
Purpose: Generate diff statistics
Calculates:
  ✓ totalLines
  ✓ addedLines, removedLines, modifiedLines, unchangedLines
  ✓ changedLines (sum of modified types)
  ✓ changePercentage = (changedLines * 100) / totalLines
  ✓ summary string ("X added, Y removed")
```

### 7. getDiffStyleSheet()
```
Purpose: Generate inline CSS for styling
Color Scheme:
  .diff-added    { background: #e8f5e9 }     (Light green)
  .diff-removed  { background: #ffebee }     (Light red)
  .diff-modified { background: #fff3e0 }     (Light orange)
  .diff-unchanged { background: #ffffff }    (White)

Marker Colors:
  .diff-added .marker    { color: #4caf50 }   (Green)
  .diff-removed .marker  { color: #f44336 }   (Red)
  .diff-modified .marker { color: #ff9800 }   (Orange)
```

```
Diff blocks
  ├→ Count by type (added/removed/modified/unchanged)
  ├→ Calculate change percentage
  └→ Generate summary string

Enables analytics and insights:
- Quick impact assessment
```

## 🔧 Core Functions

### 1. buildCommitGraphNode()
```
Purpose: Create graph node with positioning properties
Input: hash, message, author, timestamp, x, y, parentHashes
Output: Map with visualization properties

Properties:
  ✓ hash, shortHash (8 chars)
  ✓ message, author, timestamp
  ✓ x, y (SVG coordinates)
  ✓ radius (node size)
  ✓ parentHashes (array of parent commit hashes)
  ✓ children (array of child hashes, initially empty)
  ✓ level (tree depth, set by calculateNodeLevel)
  ✓ column (horizontal grouping for complex DAGs)
```

### 2. calculateNodeLevel()
```
Purpose: Compute tree depth for each commit
Algorithm:
  1. If no parents → level = 0 (root)
  2. Else → level = max(parent levels) + 1
  3. Recursive traversal of parent chain

Result: Nodes at same level = same "generation" in history
```

### 3. calculateCommitGraphLayout()
```
Purpose: Position all commits in 2D space
Process:
  1. Convert commits to nodes (with 0,0 coordinates)
  2. Calculate level for each node
  3. Find max level (deepest branch)
  4. Calculate spacing:
     ySpacing = (canvasHeight - 100) / (commitCount - 1)
     xSpacing = (canvasWidth - 100) / maxLevel
  5. Assign x = 50 + (level * xSpacing)
           y = 50 + (index * ySpacing)

Result: All commits positioned within canvas bounds
```

### 4. renderCommitNodeToSvg()
```
Purpose: Single commit → SVG circle with label
SVG Output:
  <circle cx="x" cy="y" r="8" fill="#4CAF50" ... />
  <text x="x" y="y" text-anchor="middle">shortHash</text>

Special: If merge commit (from renderMergeCommitToSvg):
  <polygon points="...diamond shape...">
```

### 5. renderCommitEdgesToSvg()
```
Purpose: Connect parent commits with dashed lines
Algorithm:
  For each node:
    For each parent:
      Find parent node in list
      Draw line: (node.x, node.y) → (parent.x, parent.y)

SVG Output:
  <line x1="50" y1="100" x2="150" y2="200"
        stroke="#999" stroke-dasharray="5,5" />
```

### 6. renderCommitGraphToSvg()
```
Purpose: Full graph → complete SVG
Order:
  1. <svg> root with width/height
  2. <rect> background (light gray)
  3. Edges (dashed lines) - drawn first (beneath nodes)
  4. Nodes (circles/diamonds) - drawn last (on top)
  5. </svg> closing tag

Canvas: 800×600 default (customizable)
```

### 7. detectMergeCommits()
```
Purpose: Identify commits with multiple parents
Algorithm:
  Filter nodes where len(parentHashes) > 1

Result: Array of merge commit hashes
```

### 8. convertCommitGraphToJson()
```
Purpose: Graph → JSON format
Output:
  {
    "format": "json",
    "totalCommits": N,
    "nodes": [
      { hash, shortHash, message, author, timestamp,
        position: {x, y}, parentHashes, level },
      ...
    ],
    "mergeCommits": [hash1, hash2, ...]
  }
```

### 9. createGraphSummary()
```
Purpose: Generate graph statistics
Calculates:
  ✓ totalCommits
  ✓ mergeCommits (count of commits with multiple parents)
  ✓ maxDepth (maximum level/generation)
  ✓ isLinear (true if mergeCommits == 0)
  ✓ summary string ("N commits, M merges")
```

## 🎓 Design Patterns

### 1. **Pipeline Pattern**
```
Raw Data → Parse → Transform → Render → API Response
           └──────────────────────────────────┘
                    Each Stage
```

### 2. **Dual-Format Pattern**
```
Canonical Format (internal)
    ├─ Render to Format A (HTML/SVG for visual)
    └─ Render to Format B (JSON for data)

Allows same source → multiple output types
```

### 3. **Type Classification Pattern**
```
Raw Input → Classifier → Type Label → Styled Output

Examples:
  - Tree: blob→📄, tree→📁
  - Diff: COPY→unchanged, ADD→added, SKIP→removed
  - Graph: 0 parents→root, 1 parent→normal, 2+ parents→merge
```

### 4. **Lazy-Loading Pattern**
```
Initial Load: Basic metadata + structural info
Lazy Flag: "loadable": true (on tree nodes, merge commits)
On Demand: Frontend requests subtree/detail data
Result: Scalability for 155+ repositories
```
