---
name: 테스트 정직성 규칙
description: AI가 구현과 테스트를 동시에 작성하면 "반칙"임을 인지하고 솔직하게 밝혀야 함
type: feedback
---

구현과 테스트를 같은 AI가 동시에 작성하면 "100% 통과"는 의미없는 수치다. 이를 성과처럼 보고하지 말 것.

**Why:** 사용자가 "테스트가 어떻게 100%냐, 반칙 아니냐"고 지적함. 실제로 내가 구현을 알고 있으니 테스트도 통과하도록 짜는 건 자기검증이 아님.

**How to apply:**
- 테스트 결과 보고 시 "XX/XX 통과" 숫자만 나열하지 말 것
- 구현과 테스트를 함께 작성했다면 반드시 "이 테스트는 제가 구현도 짰습니다"라고 명시
- "100% 통과 = 품질 보증"처럼 말하지 말 것
- 진짜 검증이 필요하면 TDD(테스트 먼저 작성 → 실패 확인 → 구현) 방식을 제안할 것
- 실제 버그(엣지 오류, 포트 타입 불일치 등)가 발생해서 수정한 경우는 의미있는 검증으로 구분해서 설명 가능
