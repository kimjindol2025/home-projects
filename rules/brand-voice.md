# FreeLang 브랜드 보이스 가이드

## 정체성

**"기록이 증명이다"** - FreeLang은 주장하지 않는다. 증명한다.

- 🎯 **기술적**: 수학적 엄밀함, 성능 검증
- 🚀 **혁신적**: 기존 방식에 도전, 새로운 가능성 제시
- 🔒 **신뢰할 수 있는**: 투명성, 오픈소스, 커뮤니티 중심
- 🌍 **한국어 우선**: 한국 개발자 커뮤니티 강화

## 톤 (Tone)

| 상황 | 톤 | 예시 |
|------|-----|--------|
| 기술 설명 | 정확하고 명확하게 | "시간 복잡도 O(n log n)의 정렬 알고리즘을 사용합니다" |
| 성능 주장 | 수치로 증명 | "기존 대비 40% 성능 향상 (벤치마크 참조)" |
| 커뮤니티 참여 | 따뜻하고 도움이 되도록 | "좋은 질문입니다! 이렇게 생각해 볼 수 있습니다..." |
| 실패 공개 | 솔직하고 학습 지향 | "이 접근법은 실패했는데, 우리가 배운 것은..." |
| 경쟁사 언급 | 존경하지만 차별화 | "Rust는 훌륭한 언어이고, FreeLang은 다른 철학으로..." |

## 언어 규칙

### 금지사항
- ❌ **과장 금지**: "가장 빠른", "최고의" (상대적 주장)
- ❌ **주관적 표현**: "훌륭한", "멋진" (객관적 지표 필요)
- ❌ **경쟁사 비방**: 존경 표현하고 차별화 강조
- ❌ **마케팅 용어**: "혁명적", "게임체인저" (기술적 사실 사용)
- ❌ **약속 지키지 않기**: 모든 공약은 타임라인과 함께

### 필수사항
- ✅ **수치와 근거**: 모든 성능 주장에 벤치마크
- ✅ **투명성**: 한계와 트레이드오프 공개
- ✅ **존중**: 다른 언어/프로젝트 인정
- ✅ **일관성**: 모든 채널에서 동일한 메시지
- ✅ **한국어 우선**: 기술 용어 제외하고 한국어 사용

## 메시지 프레임

### 문제 설정
```
기존 [언어/도구]는 [문제]가 있습니다.
예: Rust는 복잡도가 높아 학습 곡선이 가파릅니다.
```

### 해결책 제시
```
FreeLang은 [철학]으로 [문제]를 해결합니다.
예: FreeLang은 "자명함"을 원칙으로 복잡도를 줄입니다.
```

### 성과 입증
```
결과: [정량 지표]
예: 개발 시간 40% 단축, 메모리 사용 50% 감소
```

## 플랫폼별 어조

| 플랫폼 | 어조 | 형식 |
|--------|------|------|
| **블로그** | 교육적, 깊이있는 | 1,500~2,500단어, 기술 깊이 |
| **트위터** | 빠르고 영감있는 | 280자, 뉘앙스, 해시태그 활용 |
| **LinkedIn** | 전문적, 인사이트 | 500~800자, 배운 교훈, 데이터 |
| **GitHub** | 투명하고 솔직한 | 기술 정보, 한계 명확히 |
| **커뮤니티** | 친근하고 도움이 되는 | 질문 환영, 배경 설명, 링크 |

## 브랜드 특징 (5가지)

1. **수학적 엄밀함**: 모든 주장을 증명
2. **투명한 개발**: 진행 과정을 공개
3. **커뮤니티 중심**: 개발자 피드백 소중히
4. **기술적 우수성**: 성능과 안전성 우선
5. **한국 개발자 지원**: 한국어 문서, 한국 커뮤니티 우선
