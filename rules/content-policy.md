# FreeLang 콘텐츠 정책

## 필수 검증

### 1. 기술 주장
모든 기술적 주장은 다음 중 하나로 뒷받침:
- ✅ 실제 코드 예시 (실행 가능)
- ✅ 벤치마크 결과 (재현 가능)
- ✅ 공식 문서/스펙
- ✅ 학술 논문 인용

❌ **금지**:
- "~한 것 같다", "~일 가능성이 있다" (확신 없는 주장)
- 근거 없는 성능 비교
- 검증하지 않은 데이터

### 2. 성능 지표
- 항상 벤치마크 환경 명시 (하드웨어, OS, 컴파일러)
- P95/P99 같은 백분위수 사용 (평균 지양)
- 최소 3회 반복 측정
- 표준편차 또는 신뢰도 구간 포함

### 3. 비교 분석
- 경쟁사를 존경하는 톤으로 언급
- 공정한 비교만 (같은 조건에서)
- "더 낫다"가 아닌 "다르다" 표현
- 모든 비교 코드 공개 (검증 가능하게)

## 금지 사항

### 콘텐츠 금지
- ❌ 개인정보 (주민번호, 전화번호, 이메일 주소)
- ❌ 경쟁사 비방 또는 명확한 비난
- ❌ 미검증 주장 ("~라고 들었다")
- ❌ 스팸/광고성 콘텐츠
- ❌ 정치/종교/혐오 표현
- ❌ 저작권 위반

### 행동 금지
- ❌ 다른 커뮤니티 침해
- ❌ 쌍방향 동의 없는 로그인 정보 공유
- ❌ 구글 애널리틱스 추적 코드 남용
- ❌ 사용자 데이터 무단 수집

## 권장 사항

### 투명성
- 한계와 트레이드오프 명시
- "모르는 부분" 솔직하게 고백
- 실패 사례와 배운 점 공유

### 접근성
- 용어 설명 (전문 용어 제외 설명)
- 다양한 배경의 독자 고려
- 시각적 다이어그램/코드블록 활용

### 일관성
- 모든 채널에서 일관된 메시지
- 시간이 지난 콘텐츠 업데이트 (낡은 정보 제거)
- 버전별로 콘텐츠 구분

## 예시

### ❌ 피해야 할 표현

```
"FreeLang은 Rust보다 훨씬 쉽습니다."
→ 근거 없음, 주관적

"우리 벤치마크에서 100배 빠릅니다."
→ 환경 미명시, 과장 가능성

"모든 개발자가 FreeLang을 사용해야 합니다."
→ 절대적 권장, 거짓
```

### ✅ 권장 표현

```
"FreeLang은 Rust와 다른 철학으로 설계되었습니다.
Rust는 메모리 안전성을, FreeLang은 개발자 생산성을 우선합니다."
→ 존경 표현, 차별화 명확

"벤치마크 환경: AMD Ryzen 5950X, 64GB RAM, Ubuntu 22.04
같은 조건에서 10배 빠른 결과를 얻었습니다. (상세 코드: [링크])"
→ 재현 가능, 투명성

"FreeLang은 중소 팀의 빠른 프로토타이핑에 좋습니다.
대규모 시스템 성능이 필수라면 Rust를 권장합니다."
→ 사용 사례 명확, 한계 인정
```

## 리뷰 프로세스

모든 공개 콘텐츠:
1. **작성자 검토**: 기술적 정확성 확인
2. **동료 검토**: 다른 에이전트 검토 (48시간)
3. **발행**: 피드백 반영 후 발행
4. **모니터링**: 발행 후 댓글/피드백 수집 (1주)
